# سجل قرارات العقود — contract.1

**السلطة:** قرارات لتعريف التنفيذ ضمن طلب استكمال العقود؛ تابعة للمصدر ولا تعدّل بايتاته. حالة التعريف `DEFINED_FOR_IMPLEMENTATION`؛ دليل التطبيق والتأهيل مستقل. يشرح [PROTOCOL.md](PROTOCOL.md) الصيغ والحدود.

## القرارات السبعة المحمولة من المواصفة

| ID | القرار | عقد التنفيذ وفحصه |
| --- | --- | --- |
| D1 | `HOST_SIGNAL` ملاحظة اختيارية؛ `NOT_OBSERVABLE` صالح | شاهد إقرار المضيف يختلف عن شاهد التنفيذ. لا يستنتج `EXECUTED` أو `VERIFIED` من الإقرار؛ حالة ملاحظة مستقلة لكل مضيف/إصدار |
| D2 | نتائج الاكتشاف الثلاث مستقلة | `UNKNOWN_ID` رفض، `NO_SKILL_MATCH` عدم تطابق صالح، `DISCOVERY_UNAVAILABLE` إيقاف وتحذير للمسار المتأثر. لا تجاوز تفويض بدعوى التنفيذ المباشر |
| D3 | CI ينشر الحالة، والجلسة تنتج الأدلة | `.aghr/state.json` للقراءة في الوكيل وStudio؛ الأدلة منفصلة، ترفق بـPR وتقيّمها CI قبل النشر |
| D4 | اللغة للعرض | لا معامل `language` في مجموعة مرشحات التعليمات؛ اختبار ثبات مجموعة البنود بين العربية والإنجليزية مطلوب |
| D5 | صدق الإبلاغ مستقل عن جودة الاكتشاف | صدق 100%، نجاح وهمي صفر؛ تغطية العربية والإنجليزية تقاس باختبار مستقل، ولا تستنتج من عدد الاستدعاءات |
| D6 | استقبال المجلدات ينتج مسودات تغيير | امتدادات `.md/.yaml/.json`، مسار موثوق وحدود للحجم والتداخل، ولا مسح مناطق الحظر أو اتباع روابط خارج النطاق. الـwatcher معطل في هذه الدفعة |
| D7 | لا مفتاح كتابة عام | تفويض خادمي للفاعل والمشروع والفعل والمقترح وبصمته، يعاد فحصه قبل الأثر، وتبطل الموافقات عند تغير البصمة |

## أسئلة G.4 — تعريفات التنفيذ المحددة

| ID | القرار | دليل التعريف وحد التنفيذ |
| --- | --- | --- |
| D8 | غلاف task/session بحدث واحد في السطر، JSON حتمي UTF-8، وحفظ البايتات الأصلية. لا تعديل في مفتاح SQLite. | مخطط وصيغة ومحوّل مرجعي واختبارات تعدد السطور/التكرار/التعارض/الأصل. القارئ لا يمنح ثقة أو نجاحًا، ودعم المصدر الأجنبي غير المطابق لا يغير الأصل. |
| D9 | يحتفظ `host.acknowledged` بالإقرار الخام دون رفع الحالة. `HOST_SIGNAL` يحتاج الإقرار ومرجع تنفيذ حالي، فيجمع اختيارية §7.1 مع الشرط الأشد في §14.2. | قبول/رفض بنيويان؛ إثبات المضيف والتنفيذ الحقيقي ما زال NOT_RUN. لا تغيير صامت لصياغة المرجع. |
| D10 | token مؤقت مربوط بفاعل من تهيئة موثوقة؛ دور وسياق التفويض ينشئهما الخادم؛ ثقة المُصدر مستقلة. | مخطط auth، طلبات ترفض actor المزور، ودور الموافقة خانة فقط؛ تأهيل المصادقة الفعلية NOT_RUN. |
| D11 | عقد ربط المحرك والتوزيع والمحول وضوابط العمليات وحالات غيابها محدد. قالب المحرك NOT_CONFIGURED يمنع ادعاء الربط. | البنية مكتملة؛ تشغيل Python/lookup/Windows adapter/التوزيع وتأهيل المضيف REQUIRED / NOT_RUN / NOT_WAIVED. |
| D12 | إضافة submit الوحيدة تنفذ انتقال validated إلى in_review في §37؛ لا يغيرها طلب موافقة ذاتي. | الفهرس يميز 58 عملية أصلية وإضافة واحدة؛ فحص التغطية يمنع إخفاء الفرق. |
| D13 | If-Match وبصمة JCS للمقترح، وإقرارات الاختزال من stage/reason دون هوية من العميل. | أخطاء 428/412؛ الجسر يعيد الفحص قبل الأثر. حساب البصمة داخل المحرك وتأهيل CI لم ينفذا. |
| D14 | WS يحتفظ بمصادقة الرأس. المتصفح الذي لا يستطيعها يستخدم GET للمراقبة، ولا يرسل التوكن في URL. | نوع الرسالة محدد؛ ترقية WS وتأهيل العميل NOT_RUN، ولا تستنتج من مثال JSON. |
| D15 | الحقول اليومية CAPABILITY مسطحة كما في متطلبات §39؛ qualification يقبل السجل الواحد أو قائمة؛ غلاف CP مستقل عن kind. | جميع payloads لها أمثلة قبول/رفض؛ المحرك يتحقق من تغطية كل مهارة وtuple لا من مجرد وجود قائمة. |

## تفسير الحقول والتوافق

1. يطلب §6.1 `impact.evidence` لكل بند حتى لو لم يذكره جدول الحد الأدنى §3.3؛ المخطط يطبّق الطلب الصريح. لا تُستنتج أولوية من حقل `severity` وحده ولا يثبت `repo-measured` دون مسار Calibration.
2. يفرض §5.2 المستوى على `MUST_NOT` بكل درجاته. تمثيل الإنفاذ البشري `gate.type: human-approval` يعرّف التصريح؛ وجود البوابة الفعلي يحتاج doctor.
3. السجل الواحد محفوظ للتوافق مع المثال، والقائمة تمثل عدة مهارات أو عدة تركيبات تأهيل. لا تعمم qualified من سجل إلى بقية المراجع.
4. `coreKindsOnly` لا يعني حذف الأنواع التنظيمية السبعة من القاموس؛ يقيّد التأليف اليومي والمسارات والمراجعات وفق §4.2. تنفيذ هذا القرار في المحرك، وليس إعادة سياسة في Node.
5. صيغ التاريخ وفحص hash بنيويان؛ لا يثبت التطابق مع ملف أو أمر أو host. مخرجات التأهيل والتقييم تحتاج دليل تشغيل متطابقًا مع المفاتيح الأربعة، وتغير أي منها لا يرث النجاح السابق.
6. حدود الموارد الافتراضية 2048 MiB = 2 GiB. الإلغاء بطلب المستخدم يحتاج سببًا مستقلًا عن التجاوز؛ لا تُختلق حالة `resource_limit_exceeded` إذا لم تُقَس مخالفة.

تسمح الإضافات بتعريف تنفيذ متسق دون تعديل الحزمة المرجعية. يحفظ إيصال الاستكمال النسخة السابقة والفرق، ويظل إغلاق المرحلة 0 مشروطًا بدليل تشغيل بواباتها، لا باكتمال هذا السجل.
