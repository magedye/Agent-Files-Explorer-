# مهارة هندسة قواعد وتعليمات وحوكمة الوكلاء

**اسم المهارة:** `enterprise-agent-governance-rule-engineer`  
**الإصدار:** `1.0.0`  
**صيغة التوزيع:** Agent Skills (`SKILL.md` + موارد عند الحاجة).  
**الحالة:** مهارة استشارية قابلة للتشغيل ضمن عميل يدعم Agent Skills، وليست منصة تنفيذ سياسات أو شهادة اعتماد.

## ماذا تفعل؟

تحلل أي بند أو قاعدة أو سياسة أو تعليمة، سواء كان ضمن System Prompt أو ملف `AGENTS.md` أو وثيقة ضوابط أو قائمة شروط تشغيلية، ثم:

1. تحافظ على النص الأصلي والسلطة التي يدعيها دون افتراض الاعتماد.
2. تشخّص اللبس والتداخل والغموض والتعارضات وعدم التحقق.
3. تقترح **تحسينًا تحريريًا محافظًا** و**نسخة هندسية أكثر انضباطًا** عند الحاجة.
4. تميز التغييرات التي تحتاج قرار مالك عن تحسينات الصياغة العادية.
5. تحدد نوع الضبط الصحيح: Prompt أو تحقق برمجي أو تفويض خارجي أو موافقة بشرية.
6. تصمم حالات اختبار ملائمة للشرط والفشل والنطاق، مع تمييز ما لم يُنفذ.
7. تُخرج توصية واضحة `KEEP` أو `EDIT` أو `SPLIT` أو `BLOCKED_CONFLICT` وغيرها.

## وضعيات التشغيل

| الوضع | الاستخدام | المخرجات |
|---|---|---|
| QUICK | تعليمة مفردة بسيطة | تحسين سريع مع سبب واختبار |
| STANDARD | بند عادي أو سياسة قصيرة | مراجعة + بديلان + أثر + اختبارات |
| FULL | صلاحيات وأدوات وإنتاج وبيانات حساسة | مواصفة ذرية، وثقة وإنفاذ وأدلة وبوابات |
| BATCH | عشرات/مئات البنود | جدول مراجعة ومعرفات وفروق وتعارضات |
| EXPLAIN | سؤال عن معنى قاعدة | تعريف وفروق وحدود ومثال |

## الاستخدام في Codex

هذه مهارة مستقلة محمولة، ولا تتطلب Docker أو أدوات سحابية.

- **عالميًا على جهازك:** فك الضغط، وضع المجلد الكامل `enterprise-agent-governance-rule-engineer` تحت `%USERPROFILE%\.agents\skills\`.
- **لمستودع محدد:** ضع المجلد تحت `<repository>\.agents\skills\`.
- أعد تحميل جلسة Codex عند الحاجة، ثم استدع المهارة:

```text
استخدم $enterprise-agent-governance-rule-engineer لمراجعة البنود التالية.
حافظ على مستوى إلزامها وسلطتها، واقترح تحسينًا تحريريًا أولًا،
ثم تغييرات هندسية مستقلة مع درجة الأهمية ومخاطرها واختبارات قبول.
لا تعدل الملفات، ولا تفترض اعتماد القواعد أو تشغيل الاختبارات.
```

وجود مجلد صالح لا يعني أن Codex اشتغل عليه أو أن أي قاعدة قد أصبحت فعالة. تختلف مسارات التثبيت عند العملاء الآخرين.

## الفحص المحلي

من داخل المجلد:

```bash
python scripts/validate_skill.py
python -m unittest discover -s tests -v
python scripts/lint_rule.py --text "يجب أن يكون النظام آمنًا دائمًا" --format json
```

الاختبارات تفحص صحة الحزمة وقواعد lint المحددة، **ولا** تختبر امتثال نموذج ذكاء اصطناعي أو كفاءة منصة تفويض خارجية.

## قواعد الأمان

- `DRAFT` هي الحالة الافتراضية. لا ترقِّ القواعد إلى `APPROVED` أو `ACTIVE` دون دليل مستقل من الجهة المخولة.
- لا توجد أدوات أو صلاحيات تُمنح تلقائيًا؛ هذه مهارة تحليل ومراجعة.
- أدوات التحقق من الشكل (Schema) ليست بديلًا لطبقة التفويض (PEP/PDP).
- لا تخلط بين قرار صياغة القاعدة، وتنفيذ الاختبار، واعتماد النتائج، وتصريح التفعيل.
- حافظ على اللغة العربية في التقارير العربية، مع المصطلحات الإنجليزية القياسية.
