# Explicit limitations — current v1.4.0 delivery

- This is an implemented engineering candidate, not owner-accepted or automatically active.
- It guides one primary agent; it does not guarantee correctness, elimination of most errors, or a measured quality gain.
- Deterministic tests do not prove the agent uses the guidance, asks useful questions, makes correct recommendations or finishes a real task.
- New cross-artifact diagnostics require supplied scoped claims/annotations. They do not autonomously discover semantic contradictions in arbitrary natural language or code.
- Source hashes check consistency, not truth, publisher identity, authentic owner authority or honest test execution.
- Quality snapshots and reports are derived. Do not use them as a second editable task/decision system.
- Confidence ranges are optional and normally subjective. Calibration references are not scientifically verified by the checker.
- G1/G2/G5 and quality results do not grant runtime permissions, independent acceptance, scientific approval or publication authority.
- No PEP/PDP, trusted external runner, signing service, robust sandbox or orchestrator is added. Use separately qualified controls where required.
- Independent review claims are not authenticated. Another model/session alone does not prove separation.
- Recovery is reviewed, not executed. Some external effects have no true rollback; forward recovery and residual risk must be explicit.
- Live Codex, Windows path/ACL/junction behavior and current Antigravity/OpenCode integration were not qualified in this environment.
- Actual effectiveness measurements and independently held-out behavioral tests have not been run. Example counts are synthetic arithmetic fixtures only.
- Official sources were reviewed within the stated scope; no universal latest-model compatibility certificate is claimed.
- Existing v1.3.x evidence files describe those earlier executions. Only the current verification report and V140-prefixed evidence describe this delivery.
