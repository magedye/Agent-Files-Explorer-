# GOV-SDLC-PRE-001 — Freeze the existing project baseline

Mode: READ_ONLY / EVIDENCE_BASED / SELF_ASSESSMENT / NOT_INDEPENDENT.
Use for any small/medium project, one developer and one primary coding agent by default.
Do not assume a new framework is needed or import its rules into the AS-IS baseline.

Inspect actual project purpose, repository/worktree/HEAD/dirty and untracked state,
current model/host/version, authorized configuration and instruction-loading evidence.
Discover existing authoritative requirements, decisions, task records, skills and tools.
Do not infer effective loading from file existence. Do not access hidden instructions,
secrets, unrelated directories or unavailable connectors. Record access limitations.

Assess actual instruction authority, material conflicts, high-impact obligations,
delegation and runtime restrictions separately. Trace representative original requests
through requirements, tasks, implementation, evidence and acceptance. Inspect planning,
change management, documentation quality, context recovery, bug correction, false DONE,
unnecessary approvals and procedural overhead. Use historical execution evidence where
available; a policy file alone proves neither behavior nor technical enforcement.

Keep stable capability IDs M01 specifications; M02 changes; M03 planning; M04 workflow;
M05 verification; M06 delegation; M07 continuity; M08 host integration; M09 skills;
M10 evaluation; M11 owner decisions; M12 interoperability. Mark each sufficient,
partial, ineffective, missing, not needed or unknown; no automatic platform build.

For each finding record ID, evidence location/revision/hash where feasible, observed
issue, confirmed cause or hypothesis, consequence, current control and next check.
Separate FACT/CLAIM/INFERENCE/ASSUMPTION/RECOMMENDATION and confirmed finding,
potential risk, evidence gap and design opportunity. NO_TELEMETRY and NOT_RUN are
legitimate outcomes; do not invent numerical confidence or maturity scores.

Freeze a Baseline Comparison Record: project/HEAD/worktree, host/model, configuration
references and hashes, applicable rule set, requirement set, capability/finding IDs,
evidence index, verification ledger, metric definitions, raw counts/denominators,
unknowns, planned comparable tasks and fixed acceptance oracles. Use the definitions
in docs/14_QUALITY_EVALUATION.md. Examples include a bug, feature, multi-condition
request, approved-spec change, authority boundary and recovery. Do not execute new
mutating scenarios or call a published authored test set a blind holdout.

Output five concise sections: executive AS-IS, authority/loading/enforcement map,
SDLC/autonomy/skills matrix, prioritized evidence-backed findings, frozen comparison
record with missing evidence. Put detailed evidence in an annex rather than deleting it.
Return the report in the response unless writing to a named evidence directory is
already authorized. Do not modify, adopt, install, commit, publish or run unsafe tests.

Status: BASELINE_CAPTURED / BASELINE_CAPTURED_WITH_LIMITATIONS / PARTIAL_BASELINE /
BLOCKED_SCOPE. Continue independent read-only work when one item is blocked.
