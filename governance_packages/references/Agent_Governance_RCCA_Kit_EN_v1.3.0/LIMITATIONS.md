# Limits that must survive adoption

This kit cannot determine truth from a JSON claim, authenticate an owner from a local reference, or intercept
arbitrary tools. Hash integrity is not signer identity. Its paths and artifact references are explicit samples,
not a full-worktree security proof. The imported Markdown mapping is partial; raw bytes are not a normalized
semantic model. The optional continuity view does not execute tasks. The custom validator supports only the
package-owned JSON Schema subset, not general remote schemas.

The primary CLI is offline and diagnostic; use `python -B` to suppress ordinary Python bytecode cache writes.
Redirecting stdout writes to the caller-selected destination and therefore needs normal filesystem authorization.
Never redirect over an original request, approved spec, input envelope, existing evidence or protected policy.
Legacy ledger/demo tools and evaluation/tests can write within their documented authorized/temporary scope.

Version-specific docs are not live-host qualification. OpenAI full-text currency limits are explicitly recorded;
Google and Anthropic guidance are not asserted to use an identical hierarchy. No provider guarantees are inferred.

One developer can own, maintain and accept work, but calling those functions three different roles does not create
three independent people. Self-review can support routine local work; higher-risk decisions still require the
actual project's proportionate evidence and technical boundaries. No real project must adopt every shipped file.
