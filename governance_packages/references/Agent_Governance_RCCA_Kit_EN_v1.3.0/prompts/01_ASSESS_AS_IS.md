# Baseline self-assessment — read-only

Assess this existing project as it is. Do not install this kit, change instructions or adopt AG-DLF while assessing.
Use current project sources, effective host instructions and accessible execution evidence. Respect existing
permissions; do not inspect secrets or hidden prompts. Record SELF_ASSESSMENT / NOT_INDEPENDENT.

First identify the repository/workspace, current changes, goal, primary agent/host/provider and actual owner
reference. Distinguish platform capability, enabled configuration, observed use and verified behavior. Then examine
request coverage, planning/tasks, change decisions, evidence, completion, resume and relevant existing skills.
Use historical run artifacts when available; static documents alone do not establish live behavior.

Freeze the AS-IS findings before comparing functional capabilities: specification, change lifecycle, tasks,
workflow, verification, delegation, context, adapters, skills, evaluation, owner decisions and interoperability.
Those capabilities are questions, not mandatory new modules. KEEP_AS_IS and NOT_NEEDED are legitimate outcomes.

Return five compact sections: (1) environment/authority/limits, (2) capability-evidence table, (3) fit-gap decisions,
(4) highest-value improvements using existing mechanisms first, (5) actual owner decisions and next verification.
For each material claim give a path/span, inspectable output or run reference. Separate FACT, CLAIM, INFERENCE,
ASSUMPTION and RECOMMENDATION. Use NOT_VERIFIED with ACCESS_DENIED, TOOL_UNAVAILABLE, NOT_RECORDED, OUT_OF_SCOPE or
INSUFFICIENT_EVIDENCE. Denied access may be correct least privilege, not a defect. Use NO_TELEMETRY instead of
invented savings. Do not infer absence from incomplete search.

Continue all authorized read-only analysis without redundant approval requests. Stop only the affected part for
an unresolved authority/scope conflict, unsafe read or inaccessible prerequisite. Do not issue acceptance or activation.
