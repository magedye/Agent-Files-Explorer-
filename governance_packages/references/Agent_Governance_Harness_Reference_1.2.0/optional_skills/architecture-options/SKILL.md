# بدائل التصميم وقراراته

**الحالة:** مهارة أصلية اختيارية، مدمجة في التوزيع وغير مفعلة أو مؤهلة في مضيف. لا تمنح صلاحية ولا تغير مرجعية المشروع. وجود الملف في التوزيع ليس تثبيتًا أو تفويضًا.

## متى تستخدم
قرار تقني يؤثر في العقود أو المخاطر أو قابلية الصيانة.

## المدخلات
هدف وقيود ومعمارية مقبولة ومخاطر وبدائل.

اقرأ المرجعية الفعلية للمشروع ونطاق التفويض أولًا؛ إذا غابت لا تفترضها. المصدر التفصيلي داخل هذه الحزمة: [الإجراء](../../procedures/ALTERNATIVES_AND_IMPACT_AR.md).

## الخطوات
1. افحص التصميم القائم والقيود التي لا يملك القرار تجاوزها.
2. حدد البديل المطلوب وأقل بديلين مناسبين عندما توجد مفاضلة حقيقية.
3. قارن الأثر والصيانة والأمن والرجوع والتكلفة القابلة للإسناد.
4. اقترح تجربة محدودة مفوضة لحسم عدم يقين تقني.
5. سجل التوصية أو القرار المقبول دون فرض إعادة تصميم أو تنفيذ خارج النطاق.

## المخرج
مذكرة قرار مختصرة مع مبررات ومخاطر وحدود يقين.

## اختبار قبول المهارة عند التأهيل
اقتراح نقل بيانات سحابيا لتحسين الأداء: يبرز أثر الخصوصية قبل القرار.

## الحدود والتوقف
لا تفترض أن اختيار مكتبة يفوض نقل البيانات أو تغيير العقد العام.

استخدم الأدوات المتاحة والمصرح بها فقط. سجل ما نفذ فعلًا وما لم ينفذ، ولا تدّع استقلال مراجعة أو موافقة مستخدم أو نشرًا. عند عائق محلي لا توقف عملًا مستقلًا مفوضًا، إلا إذا أمر المستخدم بالتوقف.

## الأصل والتأهيل
تأليف أصلي للحزمة استجابة لطلب المستخدم، دون نقل كود أو نص مهارة من أداة خارجية. حالة التقييم السلوكي: NOT_RUN. اختيارها يحتاج مواءمة المضيف والأدوات واختبارات التحميل والأثر؛ لا تُنسخ تلقائيًا إلى مجلد اكتشاف مهارات.
