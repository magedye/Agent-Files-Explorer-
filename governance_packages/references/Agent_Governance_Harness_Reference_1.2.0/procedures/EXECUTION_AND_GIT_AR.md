# الاستمرار المتتابع وإدارة Git

**القواعد المرجعية:** AGHR-010 / AGHR-044. هذا إجراء مدمج في AGHR 1.1.0؛ السجل المعياري الوحيد هو [RULES](../registry/RULES.json).
## وضعان ضمن المرجعية نفسها
الوضع الموجّه يتوقف عند القرارات المادية اللازمة. الوضع المتتابع المختار يواصل العمل المصرح به دون تدخل روتيني. لا يغيّر الاختيار مصدر الحقيقة أو صلاحيات الأدوات أو مستوى إثبات الادعاءات. عدم توفر مهمة خلفية أو جلسة مستمرة في المضيف يمنع الوعد باستمرار خارج قدراته.

يجب معرفة الهدف والنطاق والأفعال المسموحة والمحمية والمراجع وشروط التوقف وما الذي يثبت نجاح المهمة. تضاف حدود ميزانية أو زمن أو محاولات فقط إذا قررت فعلًا؛ لا يُختلق سقف معياري. تحافظ الحلقة على نقطة استئناف وعلى أقل تحقق مناسب لكل دفعة، مع عدم إضعاف الاختبار لإكمال الحلقة.

## حلقة التنفيذ
تستعيد الحالة الفعلية، وتختار مهمة مرتبطة بالخطة، وتفحص تفويضها واعتمادياتها، وتنفذها، وتتحقق، ثم تحدث الدليل والحالة. بعد كل دفعة يُراجع تقدم الهدف لا عدد الأوامر. الفشل المتكرر بلا معلومة جديدة يستلزم تشخيصًا أو توقفًا مفسرًا، لا مزيدًا من المحاولات العمياء.

تتوقف الأعمال المتأثرة عند طلب المالك أو غموض جوهري أو تعارض مرجعي أو غياب أصل ضروري أو أثر خارج التفويض أو تجاوز ميزانية معلومة أو فقد بيئة تحقق لازمة. لا تتجاوز توقف المالك بمواصلة «عمل مستقل»؛ هذا الاستثناء فقط لعائق موضعي لا لأمر إيقاف شامل.

## اكتشاف Git دون تغيير غير لازم
يفحص الوكيل ما إذا كان المسار مستودعًا أصلًا، والفرع الحالي أو HEAD المنفصل، والتعديلات غير المحفوظة والفروع/worktrees ذات الصلة، والبعيد والفرع الافتراضي إذا أمكن التحقق منهما. عدم الاتصال أو عدم التفويض للوصول البعيد يُذكر كحد للرؤية. لا يزعم حصر جميع الفروع البعيدة من نسخة محلية قديمة.

يذكر الفرع عند بدء عمل جوهري، وعند تغييره، وعند التسليم؛ لا حاجة لتكراره في كل جملة. التنبيه إلى فروع أخرى يقتصر على العمل المرصود ذي الصلة، دون عرض محتوى خاص أو استنتاج أن كل فرع يجب دمجه الآن.

## جاهزية الدمج وإغلاق الفرع
الهدف الوصول بعمل مكتمل إلى المسار المعتمد بدل ترك فروع منسية؛ لكنه سعي مشروط لا أمر دمج دائم. افحص هوية المرشح والدليل وصلاحية المراجعة وشروط الفرع وتفويض الدمج. افصل commit عن push وعن merge وعن حذف الفرع وعن release وعن التفعيل. لا يفوض اختيار الوضع المتتابع هذه الأفعال تلقائيًا.

الدمج بأسلوب squash أو إعادة الأساس قد لا يجعل كل commit قديم سلفًا مباشرًا للفرع الهدف؛ لذلك افحص سجل طلب الدمج أو تطابق التغييرات المناسب بدل الجزم من اختبار ancestry وحده. هذا تنبيه لتصميم إجراء التحقق، وليس إثبات دمج لأي مستودع هنا.

بعد الدمج افحص النسخة المتكاملة بالقدر المناسب، وتحقق من المزامنة المصرح بها، ثم عد إلى الفرع الافتراضي إذا لم يعرقل ذلك عملًا آخر أو worktree قائمًا. لا تغيّر الفرع قسرًا، ولا تحذف فرعًا غير مدمج أو stash أو تعديلًا يخص المستخدم، ولا تفرض main بدل اسم الفرع الفعلي.

## التسليم عند تعذر الإغلاق
اذكر الفرع والسبب المحدد لتعذر الدمج، والأدلة المنجزة وغير المنجزة، وما يحتاجه المستخدم بالضبط. احتفظ بالعمل آمنًا، ولا تسمّه مندمجًا أو متزامنًا دون تحقق. لا ترجع تلقائيًا تغييرات آمنة فقط لتحسين شكل التقرير.

هذه إجراءات مرجعية مدمجة تحتاج تبنيًا وتأهيلًا داخل المشروع؛ ضوابط المضيف الرسمية [OA-15](../sources/REGISTER_AR.md) تحتاج فحصًا على النسخة المثبتة. الأدوات المرفقة لا تجري أي أمر Git.
