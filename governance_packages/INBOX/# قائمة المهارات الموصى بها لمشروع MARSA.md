# قائمة المهارات الموصى بها لمشروع MARSAD

مصنفة بحسب **دورة حياة الشريحة** في MARSAD، مع توضيح الوظيفة والمرحلة والنتائج والمدخلات. أُدرج فقط المهارات **المعلنة** (القابلة للاستخدام)، وأُشير إلى غير المعلنة في قسم منفصل.

---

## القسم أ — مهارات الميتا (Meta) — تُستخدم قبل كل شريحة

| المهارة | الوظيفة | المرحلة | المدخلات المطلوبة | النتائج المتوقعة |
|---|---|---|---|---|
| **using-agent-skills** | موجّه داخلي لاختيار المسار (استيضاح → مواصفة → تخطيط → تنفيذ → اختبار → مراجعة) | قبل الشريحة | تفويض معتمد + نص الشريحة + قيود MARSAD | اختيار مسار محدد + إظهار افتراضات + كشف تعارضات قبل التنفيذ |
| **context-engineering** | تنظيم السياق عبر الجلسات والشرائح | كل شريحة | TASKS.md، PROJECT_STATE.md، DEFERRED_REGISTRY، ODRs، تفويض سابق | استئناف دقيق دون فقدان سياق + لا اختراع قرارات |

**قاعدة**: `using-agent-skills` **موجّه تابع**، لا مشرّع مستقل. لا تلغي بوابات MARSAD.

## القسم ب — مهارات التخطيط والعقد

| المهارة | الوظيفة | المرحلة | المدخلات المطلوبة | النتائج المتوقعة |
|---|---|---|---|---|
| **spec-driven-development** | تحويل المتطلب إلى عقد + معايير قبول | قبل كتابة الكود | نص الشريحة + العقد المراد الحفاظ عليه (مثل AnswerContract، DataTable JSON) | وثيقة عقد + AC قابلة للاختبار + تعريف "خارج النطاق" |
| **planning-and-task-breakdown** | تفكيك الشريحة إلى خطوات مرتبة بمخارج واضحة | تالٍ للمواصفة | وثيقة العقد + قيود الملفات | قائمة مهام مرتبة + تبعيات + حدود ملفات (allowlist) |
| **interview-me** | استيضاح الغموض في الطلب | قبل المواصفة عند غموض | طلب أولي غامض | أسئلة محددة + توضيح النطاق |
| **idea-refine** | تقييم بدائل التصميم | عند اختيار بين خيارين معماريين | خيارات التصميم + معايير الحسم | تحليل بدائل + افتراضات مكشوفة |

**قيود**:
- `interview-me` للاستيضاح فقط، لا لتوليد متطلبات جديدة. الغموض في نطاق معتمد = STOP وسؤال المالك.
- `idea-refine` مسموحة في مرحلة التخطيط، لا في التنفيذ.

## القسم ج — مهارات التنفيذ

| المهارة | الوظيفة | المرحلة | المدخلات المطلوبة | النتائج المتوقعة |
|---|---|---|---|---|
| **incremental-implementation** | تقسيم التغيير إلى أجزاء قابلة للتحقق | التنفيذ | خطة المهام + allowlist | تغييرات صغيرة، كل واحدة معزولة وقابلة للمراجعة |
| **source-driven-development** | إسناد القرارات إلى مصادر رسمية | أثناء التنفيذ | وثائق رسمية (Python، Pydantic، SQLAlchemy، pytest، ...) | لا قرارات "من الذاكرة" — كل قرار مع مرجعه |
| **debugging-and-error-recovery** | تشخيص منهجي للأعطال (إثبات السبب قبل الإصلاح) | عند فشل اختبار أو CI | stack trace + سجلات + اختبار معطّل | تشخيص جذري موثق + إصلاح محصور في النطاق |

**قيود**:
- `incremental-implementation`: أي جزء خارج الـallowlist = رفض ذاتي قبل التنفيذ.
- `source-driven-development`: عند غياب مصدر رسمي، يُسجَّل كافتراض، لا كقاعدة.

## القسم د — مهارات المراجعة والتحقق

| المهارة | الوظيفة | المرحلة | المدخلات المطلوبة | النتائج المتوقعة |
|---|---|---|---|---|
| **code-review-and-quality** | فحص ذاتي للكود قبل التسليم | قبل Push | diff التغييرات + AC | كشف ذاتي لعيوب + تحسينات قبل النشر |
| **codex-security:security-diff-scan** | تدقيق أمني للفروق | عندما يُلمس سطح أمني (auth, input, SQL, secrets) | diff + سياسة الأمن | كشف حقن، تسريب أسرار، تحقق صلاحيات |
| **codex-security:verify-fix** | التحقق من إصلاح ملاحظة أمنية | عند الرد على ملاحظة مراجعة | ملاحظة أمنية + الإصلاح المقترح | تأكيد أن الملاحظة عولجت دون آثار جانبية |
| **codex-security:validation** | إثبات/نفي نتيجة أمنية مرشحة | عند الاشتباه في ثغرة | فرضية الثغرة + الكود | إثبات أو نفي موثق |
| **codex-security:assess-patch-risk** | تقييم مخاطر رقعة قبل الدمج | قبل الدمج | diff + تاريخ المنطقة | تصنيف مخاطر (منخفض/متوسط/مرتفع) |

**قيد حرج**:
> `code-review-and-quality` = **فحص ذاتي فقط**. لا تُقبل أبداً كـ"المراجعة المستقلة" المطلوبة لبوابة الدمج. المراجعة المستقلة تحتاج قناة منفصلة موثقة (وكيل مختلف، جلسة Read-Only، أو إنسان).

## القسم ح — مهارات غير معلنة (لا تُستخدم حتى تُعلن)

هذه **موجودة كملفات** لكنها **غير معلنة لهذه الجلسة**، فلا يمكن الاعتماد عليها:

| المهارة | الحالة | الأثر على MARSAD |
|---|---|---|
| **review-agent** | مثبتة، غير معلنة | **فجوة حرجة**: لا قناة مراجعة نظامية للدمج |
| **gh-fix-ci** | غير معلنة | لا يمكن الاعتماد عليها في إصلاح CI |
| **yeet** | غير معلنة | لا يمكن استخدامها للنشر — استخدم أوامر git/gh مباشرة |
| **github / gh-address-comments** | غير معلنة | إدارة PR يدوياً عبر `gh` CLI |

## القسم ط — مهارات AGHR المرجعية (غير مثبتة في مسار الاكتشاف)

11 مهارة في `Agent_Governance_Harness_Reference_1.2.0/optional_skills` — **أصول مرجعية فقط**. الآتي **يجب تثبيتها** لأنها تطابق منهجية MARSAD:

| المهارة | لماذا يهم MARSAD |
|---|---|
| **governed-learning** | "الدليل يسبق القاعدة" — استخراج دروس وتصنيفها |
| **safe-git-closeout** | بوابة الدمج/النشر بخطوات موثقة |
| **requirements-traceability** | ربط المتطلب بـAC والدليل |
| **risk-based-verification** | تحديد ما يُثبته الدليل وما لا يُثبته |
| **plan-drift-review** | مراقبة زحف النطاق |
| **smart-clarification** | حسم الغموض دون اختراع مطلب (بديل أفضل من `interview-me`) |

**توصية**: فتح شريحة Read-Only صغيرة `S-GOV-1` بعد إغلاق S10-B2 لتحديد مسار التثبيت الصحيح.

## القسم ك — مصفوفة سريعة: المهارة ← متى ← ماذا تُنتج

```
المهمة قادمة
    │
    ├─► غامضة؟ ──────► interview-me  [أسئلة محددة]
    │
    ├─► معتمدة؟ ─────► spec-driven  [عقد + AC]
    │                       │
    │                       └─► planning  [خطة + allowlist]
    │                               │
    │                               └─► incremental  [أجزاء صغيرة]
    │                                       │
    │                                       ├─► source-driven [مراجع]
    │                                       │
    │                                       └─► عطل؟ ─► debugging
    │
    ├─► قبل Push ────► code-review (ذاتي) + security-diff-scan (إن لُمس سطح أمني)
    │
    ├─► Push ────────► git-workflow
    │
    └─► Merge ───────► مراجعة مستقلة (قناة موثقة) + CI
```

## توصيتي النهائية

1. **اعتمد الأقسام (أ)–(هـ) الآن** — هذه هي الترسانة التشغيلية لـMARSAD.
2. **أجّل الأقسام (و)–(ز)** حتى تصل لمراحلها (S11 / التقييم).
3. **سجّل الأقسام (ح)–(ط) كفجوات مؤسسية** في `PROJECT_STATE.md`، وأوصِ بشريحة `S-GOV-1` بعد إغلاق S10-B2.
4. **أضف هذا الجدول في كل تفويض قادم** كقسم `Skills Authorized` — يمنع اعتماد الوكيل على مهارات غير متاحة أو استبدال مراجعة مستقلة بمراجعة ذاتية.

هل تريد أن أُصيغ الآن **وثيقة `SKILLS_AUTHORIZED.md`** قابلة للإيداع في `docs/00-authority/` لتكون المرجع الرسمي لكل تفويضات MARSAD القادمة؟
