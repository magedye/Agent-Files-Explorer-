أوصي باختيار الخيار الثالث: تعديل الضوابط المقترحة، ثم اعتماد ما ثبت أنه غير مغطى فقط. لا أنصح بتطبيق التعديل المقترح على `AGENTS.md` كما هو، ولا بإنشاء Skill جديدة قبل التحقق من الإجراءات الموجودة.

المقترح يتضمن خمسة دروس جيدة، لكنه يخلط بين القواعد العامة لحزمة AGHR، والإجراءات التقنية المتخصصة، وتعليمات مشروع Agent-Files-Explorer.

## تقييمي للدروس الخمسة

| الدرس                            | تقييمي                                        | التصرف الموصى به                                                                      |
| -------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------- |
| `_INBOX/` لا يمنح تفويضًا        | صحيح وأساسي، ومبدأ حدود التفويض موجود أصلًا   | تثبيت الإحالة إلى إجراء Inbox، وعدم تكرار كامل السياسة                                |
| مصدر واحد لحالة المشروع          | صحيح، لكنه مغطى في AGHR                       | تأكيده في موضعه الحالي؛ وعدم فرض `.aghr/state.json` إذا اعتمد المشروع متتبعًا آخر     |
| Windows وUTF-8                   | مهم، لكن صياغة `.as_posix()` حصريًا غير دقيقة | إدراجه في إجراء التوافق والملفات، وليس كقاعدة عامة مطلقة                              |
| ميزانية السياق والإفصاح التدريجي | مغطى في AGHR مع إمكانية التحسين               | الاحتفاظ بالتوجيه المختصر، وعدم فرض حد 1,000 Token كشرط قبول                          |
| حفظ بصمات خط الأساس              | صحيح ومغطى من حيث المبدأ                      | التحقق عند إنشاء المرشح وعند البوابات المهمة، وليس إعادة حساب كل البصمات بعد كل عملية |

### تصحيح تقني مهم

استخدام `Path.as_posix()` مناسب لتوحيد تمثيل المسارات النسبية المسجلة في Manifests والتقارير المحمولة، لكنه ليس بديلًا عن `Path.resolve()` أو فحص المسارات الفعلية وSymlinks. لذلك عبارة «Always use `.as_posix()` for relative path operations» واسعة ويجب تصحيحها.

وكذلك ينبغي استخدام UTF-8 صراحة للملفات النصية التي تمتلكها الحزمة، مع مراعاة الملفات الخارجية ذات الترميزات المختلفة، وعدم إعادة ترميزها صامتًا.

## أين توضع التعليمات؟

| الموضع                         | ما يستحق إضافته                                                     |
| ------------------------------ | ------------------------------------------------------------------- |
| `AGENTS.md`                    | إحالة قصيرة إلى سياسة Inbox وحدود التفويض، عند عدم وجودها           |
| `procedures/PROJECT_INBOX.md`  | تفاصيل اكتشاف الملفات وتصنيفها والمصالحة والتطبيق المحكوم           |
| إجراء التوافق أو أدوات الملفات | UTF-8 وتمثيل مسارات Manifest والتعامل الآمن مع Windows              |
| سياسة السياق والاستئناف        | إحالات إلى مصدر الحالة المعتمد والعروض المشتقة إذا كانت ناقصة       |
| أدوات الاختبار والتحقق         | اختبار أن `_INBOX/` لا يمنح سلطة، وأن الأرشيفات والبصمات تبقى سليمة |

ملاحظة نطاق: المسارات السابقة داخل الحزمة المرشحة، وليست تصريحًا بإنشاء ملفات موازية داخل Agent-Files-Explorer.

## الإجابة التي أوصي بتقديمها للوكيل

أختار **الخيار الثالث: تعديل الضوابط المقترحة قبل اعتمادها**.

راجع الدروس الخمسة مقابل السياسات والعقود والإجراءات والمهارات والاختبارات الموجودة بالفعل في AGHR Candidate 1.2.0، وصنّف كل بند إلى `COVERED / PARTIAL / MISSING / CONFLICT` مع دليل التغطية.

اعتمد الدروس المثبتة غير المغطاة فقط، وفق توزيعها الصحيح:

1. اجعل `AGENTS.md` مختصرًا، وأضف إحالات ضرورية فقط إلى قواعد `_INBOX/` وحدود التفويض.
2. ضع إجراءات Inbox التفصيلية في `procedures/PROJECT_INBOX.md` أو الإجراء المالك الحالي.
3. عالج توافق Windows وUTF-8 في الأدوات والإجراءات المتخصصة. استخدم `.as_posix()` لتوحيد المسارات المرجعية المحمولة، لا لجميع عمليات المسارات.
4. حافظ على مصدر حالة واحد، واجعل `CURRENT.md` و`HANDOFF.md` عروضًا مشتقة أو لقطات تسليم لا تنافس المصدر المعتمد.
5. اجعل ميزانية السياق قابلة للضبط، واسترجاع الأرشيفات عند الحاجة، دون حظر وصول أدوات التدقيق إليها.
6. تحقق من سلامة خط الأساس والبصمات عند البوابات ذات الصلة، دون فحص شامل متكرر غير ضروري.

لا تنشئ مهارة `aghr-inbox-governance` إلا إذا ثبت أن إجراء Inbox الحالي لا يكفي وأن المهارة تضيف سير عمل متكررًا مستقلًا يستحق إعادة الاستخدام.

**افصل تحديث حزمة AGHR عن تحديث Agent-Files-Explorer.** لا تعدل `AGENTS.md` الخاص بالمستكشف أو تضع فيه إحالات ثابتة إلى Candidate 1.2.0 بهذا الطلب.

نفّذ التحديثات المؤهلة داخل المرشح فقط، واختبرها، وقدّم مصفوفة بالدروس المدمجة والمغطاة والمؤجلة، مع بيان الملفات المعدلة ونتائج التحقق. لا تغيّر الإصدار الأصلي ولا تمنح اعتمادًا أو تنشر تلقائيًا.

الخلاصة: المقترح مناسب كأساس للمصالحة، وليس كـPatch جاهز للتطبيق. والأفضل إعطاء الوكيل التعليمات أعلاه، حتى يحتفظ بالدروس الخمسة دون تضخيم `AGENTS.md` أو ازدواجية المهارات، مع عدم الخلط بين الحزمة المرجعية والمشروع الذي يستعرضها.
