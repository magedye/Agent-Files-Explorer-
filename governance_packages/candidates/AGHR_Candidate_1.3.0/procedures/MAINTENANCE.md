# Controlled maintenance

Review when a model/host/SDK, permission mode, tool schema, source policy, data route or security advisory changes. Periodic review cadence is a project choice, not an automatic scheduled task in this package.

Check official-source applicability and deprecations, loaded instruction drift, duplicate/stale rules, skill trigger overlap, command validity, evidence freshness, open exceptions, unowned blockers and protected-route coverage. Compare representative outcome and negative-path evaluations before/after a material change.

Record changes through intake. Keep source history, accepted baselines and rollback. Do not rewrite already captured evidence or declare a new model universally safer from a small sample. Improve latency/context by removing measured waste, not safety requirements. Release package revisions with explicit compatibility notes, manifest and actual verification results.

Review affected lessons under [governed learning](GOVERNED_LEARNING.md) when their candidate, contract, evidence or review trigger changes. Preserve predecessor records and decisions. Do not retire or rewrite an accepted instruction merely because an untrusted lesson proposes supersession.
