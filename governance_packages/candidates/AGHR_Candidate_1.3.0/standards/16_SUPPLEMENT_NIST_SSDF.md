# مرجع تكميلي: NIST SSDF 1.1

**الطبقة التنظيمية:** أمن الأنظمة والوكلاء.

**الانطباق المقترح:** التطوير البرمجي الآمن ضمن دورة حياة المنتج؛ ليس قائمة إلزام عامة غير قابلة للتكييف.

## ما تم التحقق منه

الصفحة الرسمية تصف 1.1 بأنه نهائي؛ ليست قائمة تحقق جامدة. لا يُستنتج عدم وجود مسودات أخرى. [NIST-SSDF](../sources/REGISTER_AR.md)

## ضوابط تطبيقية مقترحة وليست نصوص المعيار

**حدود القراءة:** لم تُنفذ مطابقة بندية شاملة للنص الأصلي. المعرفات REC أدناه من إنشاء هذه الحزمة، وليست أرقام بنود ISO أو NIST أو OWASP. تُربط بضوابط المشروع وبنود النسخة المرخصة عند التبني التفصيلي ولا تُعلن امتثالًا.

### REC-16-01 — تهيئة التطوير الآمن
حدد المسؤوليات والأدوات والبيئات والسياسات اللازمة قبل كتابة تغيير مؤثر.

**الدليل المقترح:** سياسة تطوير وبيئة مؤهلة.

### REC-16-02 — حماية المكونات
اضبط أصل الاعتماديات وتعديل الكود وتخزين المرشحات وإتاحتها.

**الدليل المقترح:** سجل مكونات وإثبات مصدر وصلاحيات.

### REC-16-03 — إنتاج برمجيات آمنة
طبّق تصميمًا ومراجعة واختبارات أمنية مناسبة لمخاطر التغيير.

**الدليل المقترح:** تهديدات ومراجعة واختبارات رفض وسماح.

### REC-16-04 — معالجة الثغرات
جهز فرز الثغرة وتصحيحها وقياس أثرها ومنع تكرار سببها.

**الدليل المقترح:** سجل ثغرة وتصحيح واختبار انحدار.

### REC-16-05 — إدارة التوريد
صرح بحدود التغطية والاعتماد على مزود أو مكون خارجي.

**الدليل المقترح:** تقييم مورد وفجوات ومعالجة مخاطر.

## الاعتماد والتحقق

يعين المشروع مالك الضابط وطريقة فحصه وحد قبول ومصدر دليل مناسبين. مصدر الدليل قد يكون تكوينًا أو اختبارًا أو سجل قرار، ولا يكفي التصريح اللفظي بالالتزام. تكون عدم الانطباق والاستثناءات مبررة، ولا تُحوّل إلى نجاح اختبار.

لا يُحزم النص المدفوع أو الكتاب أو دليل الطرف الثالث داخل هذه الحزمة. عند الحاجة لالتزام تعاقدي أو شهادة أو قائمة ضوابط معيارية كاملة، تُراجع النسخة المرخصة والتعديلات النافذة ويجري التدقيق المناسب.
