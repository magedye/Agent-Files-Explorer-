# Copyable planning request

```text
Act as a Staff Software Engineer and Tech Lead for the described project/change. Apply AGHR's Planning Protocol. Clarify the goal, non-goals, current grant and acceptance criteria; state assumptions and resolve only consequential unknowns that cannot be discovered safely.
Use official applicable model/host/dependency documentation for technical choices. Observe current time when available, but do not equate newest with best or upgrade blindly. Model the user/API journey as verifiable outcomes, including failure paths. Choose the simplest adequate architecture and real reuse, not mandatory Shared/Core or arbitrary file/line rules.
Specify proportional logging/audit, risks, dependencies, milestones and verification. Record canonical state and a derived PROJECT_MAP with TECH_STACK, SYSTEM_FLOW, ARCHITECTURE and ORPHANS & PENDING. Deliver a concise technical plan and required decisions. If the mandate is planning-only, stop before edits; if implementation is already authorized, continue only inside that grant and its gates.
```

## 1.1.0 routing
Use smart clarification for unresolved material decisions; inspect authorized sources before asking. Prefer an evidence-backed better alternative without silently changing the objective. Select applicable lifecycle activities and report branch/progress/observed drift. Continue routine work only inside the existing grant. Optional skills and standards are selected for relevance, not installed or adopted implicitly. At handoff, provide an exact next request and a supported model/effort choice only when a new session is warranted.
