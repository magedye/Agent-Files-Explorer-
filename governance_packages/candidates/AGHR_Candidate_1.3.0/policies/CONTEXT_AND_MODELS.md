# Context, models and skills

**Rules:** AGHR-006–008, AGHR-027–028, AGHR-038. **Technical sources:** OA-02/03/12/13 and AN-01/02.

## Progressive disclosure
An always-loaded entry contains only durable boundaries and routing hints. The active request contributes the goal, criteria and grant. Retrieve paths/symbols/ranges when needed; expand when dependencies require more context. Avoid a universal line limit or blanket ban on lockfiles. Keep large raw outputs in approved artifacts with digest and bounded excerpts.

A skill description states the distinct task that triggers it. Avoid broad overlapping triggers and compulsory invocation of unrelated skills. Skills contain workflow-specific guidance, not parallel policy. Review their source and executable resources before enabling them. A project may use no skills if ordinary tools suffice.

Use native host discovery and explicit metadata observations. A small selection section can link existing project requirements and phase preferences without copying all SKILL.md files or creating another canonical store. Reevaluate when phase needs change; no universal one/two-skill cap applies. Follow [capability review](../procedures/EXTERNAL_CAPABILITIES_AR.md) and preserve loading/execution/evidence distinctions.

## Durable memory
Separate approved decisions from observations and model hypotheses. Before compaction preserve IDs, accepted boundaries, current work, pending effects, changed files, evidence references and the next safe action. Never copy secret values or private reasoning into checkpoints. After compaction or resume, reconcile the checkpoint with actual repository and current authorization. A summary does not authenticate its own facts.

## Selecting and changing a model

Lessons use the existing canonical intake and [governed learning procedure](../procedures/GOVERNED_LEARNING.md). Retrieve only currently applicable accepted guidance for the active task; keep candidate, rejected, stale and superseded claims labeled. Do not mirror project records into global host memory or make confidence a substitute for evidence and authority.
OpenAI/GPT is the default provider family, not a permanently pinned latest alias. At adoption record the chosen documented model ID/snapshot or explicit host opacity, endpoint, host/version, capabilities and available effort controls. Evaluate task quality, safety behavior, cost/latency and tool protocol against the project's fixtures. Use a more capable model or longer effort where demonstrated useful, not for every task.

On model/host/SDK or policy changes, evaluate affected scenarios, instruction loading and tool boundaries. Compare with the prior profile, record intentional changes and preserve rollback. Model-specific advice to simplify prompts never removes externally enforced safety or required evidence. Unknown capabilities remain unavailable until qualified.

## Latency and budget

Formulate bounded delegated tasks with relevant files/contracts, expected behavior, criteria, constraints and a resume point when needed; allow authorized discovery of missing facts. Choose model/effort from actual complexity, ambiguity, risk, available capabilities and measured performance. Fast/reasoning labels or using another model alone do not establish quality or independent review.
Record time in exploration, model calls, tool execution, waits and verification when useful. Reduce redundant context, tool ambiguity, full-suite repetition and no-progress retries. Do not trade away required checks, data controls or approval boundaries. A short prompt is not necessarily good: retain enough information to define the task and constraints.

## Observable explanation
Collect selected sources, tool decisions, concise rationales, outcomes and resource measures. Do not require internal chain-of-thought. Provider-required opaque continuation state is protocol material: preserve it through the adapter but do not interpret it as authority or a review record.
