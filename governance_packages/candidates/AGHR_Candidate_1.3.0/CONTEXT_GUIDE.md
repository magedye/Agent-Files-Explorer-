# AGHR 1.2.0 context and retrieval guide

Load the active request, current authorization, declared canonical state and relevant router first. The library is consulted by task through [CONTENTS](CONTENTS.md); do not preload it.

Use targeted rule IDs, exact paths and bounded ranges. Expand when dependencies or a consequential conflict require it. Historical compatibility, verification and frozen-design material is for on-demand audits; deterministic integrity/test tools may inspect it without loading its content into prompts.

Context budgets are project-configured advisories. Character-count/4 is an estimate, not a measured tokenizer count or a universal acceptance threshold. The current checker reports the actual entry-file estimates. No claimed percentage reduction establishes behavioral compliance.

A project may use .aghr/state.json or its declared native tracker. CURRENT/HANDOFF/maps are derived observations; no consumer is required to have the Studio's docs/status path. Resume from the actual repository, current grant and valid evidence.

For a learning review, retrieve the owning procedure, relevant source/candidate/evidence and applicable accepted lesson references. Candidate, rejected, stale and superseded content keeps its labels. Follow [governed learning](procedures/GOVERNED_LEARNING.md) and preserve only task-relevant references in the next startup brief.
