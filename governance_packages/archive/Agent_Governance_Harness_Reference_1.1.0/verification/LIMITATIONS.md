# Assurance limits and residual qualification — 1.1.0

This is the integrated complete reference, not an automatic deployment, vendor endorsement, certified management system or grant of authority. Original architecture and rule identities are preserved; content and executable reference helpers have been updated. The original1.0 narrative and results remain separately labeled historical, not current verification.

The source register has56 records:30 inherited developer/host records plus26 deduplicated new references.29 relevant official pages were opened for selected guidance, metadata and scope during this merge; the other inherited pages were not all independently re-audited. Full licensed ISO texts and complete humanitarian handbooks were not reviewed in this merge. The16 cards and80 recommendations are a bounded reference synthesis, not a full normative-control list, a conformity claim or certification. Humanitarian guidance applies only when context warrants it.

The six provider and six host routes remain documentation-only. The36 original and24 added model/host scenarios are NOT_RUN: no native Codex/Claude/Gemini/OpenCode/Copilot execution, real credentials, model response, production migration or external approval was tested. No independence or release acceptance is granted. Comparing record booleans does not demonstrate intelligent clarification; asking the right natural-language question and safely using real tools require behavioral testing on the selected host.

The bundled Python executor mediates only three local file operations under its trusted-caller/private-workspace assumptions. It does not mediate arbitrary shell, network, MCP or Git actions; eliminate hostile operating-system races; authenticate people; or persist replay protection and audit custody across restarts. Operating-system isolation, all-route mediation, durable authenticated logs and service authorization remain adopter responsibilities. The new progress command is read-only and does not expand that executor.

REQUEST/STATE extension checks validate declared structure, references and artifact bytes. They do not prove that a decision issuer is competent or that a test producer is honest. Clarification records are not wired as an automatic execution gate. The host must bind decisions, current policy identity, grants and effects. Full measurement scope is caller-declared; zero data is unknown, not100% complete. Progress never reports overall compliance or grants release acceptance. Missing Git/remote observations remain unknown. Historical evidence conflicts need explicit reconciliation; do not delete inconvenient failures or accept a forged waiver.

Version1.1 readers accept legacy unextended records. Unmodified1.0 readers are not promised to accept the optional fields. An existing `.aghr` must undergo a reviewed migration; it must not be overwritten with `init`. External canonical-tracker integration requires a qualified adapter; no vendor tracker connector is implemented. Optional skills are outside auto-discovery and uninstalled; copying a SKILL.md without resolving its references is not a qualified installation.

Local runtime/tests target Python3.10+ with standard-library dependencies only. Actual execution was Python3.13.5 on Linux. Python3.10 grammar parsing is not execution under that version. Windows/macOS and other interpreters were not tested. The optional HTML authoring tool uses Mistune and BeautifulSoup; these are not runtime dependencies and are not installed automatically. The resulting HTML uses no external scripts/fonts. Desktop/mobile Chromium samples are not a full browser/accessibility certification.

Before use in an actual project: establish real facts and source authority, obtain the applicable adoption decision, qualify model/host loading and protected routes, and bind evidence to that project. Product acceptance, independent review, Git merge/push, publication and activation retain separate authority. None was performed on a user project in this merge.
