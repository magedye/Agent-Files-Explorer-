# Templates

Templates are explicit unfinished records, not placeholder product implementations or approval evidence. Populate only applicable fields from actual observations. Use JSON for machine checking or Markdown for proportionate human intake; do not maintain independently edited copies of the same state. Choose a canonical representation.

The initializer copies the full reference as a local library and creates a proposed entry router. It never copies sample claims into effective project authority. `PROJECT.json` and `STATE.json` are intentionally not adoption-ready. `EVIDENCE.json` starts at NOT_RUN. Use DECISION, HOST_QUALIFICATION, PLAN, IMPACT_REVIEW, INCIDENT and HANDOFF only when their triggers apply.

Use `OPERATING_CONTRACT.md` to record actual tool-route boundaries, budgets and data decisions; link to canonical JSON/tracker facts rather than duplicating their authority.

The optional REQUEST clarification and STATE delivery fields reuse the existing contracts. See [field mapping](DELIVERY_RECORD_MAPPING.md), [standards applicability](STANDARDS_APPLICABILITY.md), and [capability review](CAPABILITY_REVIEW.md). A recorded grant reference or mode is not permission.
