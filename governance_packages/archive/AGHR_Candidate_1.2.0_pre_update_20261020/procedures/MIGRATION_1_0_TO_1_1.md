# Migration from 1.0.0 to 1.1.0

This distribution is a complete additive edition, not an in-place automatic deployment. Preserve the existing project, outstanding branches and effective policy before migration. Do not overwrite a project's `.aghr` or root instructions with a new `init`.

1. Record the current reference, source of truth, grants and candidate; retain a rollback copy in approved custody.
2. Compare the four refined rules (010, 011, 023, 038) and seven added rules (041–047), then reconcile project obligations and proper authority. No historical acceptance transfers.
3. Replace only the reviewed reference payload through the project's authorized workflow; leave global host configuration untouched. Preserve current project facts/state and deferred work.
4. New readers accept old REQUEST/STATE records. New optional fields are not compatible with an unmodified 1.0 reader. Upgrade the validator before using them; rollback must preserve richer records in custody and use a reviewed projection rather than delete them silently.
5. Bind adopted policy identity/version in the host, requalify materially affected loading/permission routes and invalidate only affected evidence.
6. Regenerate the derived map with the updated tool after authorization. Run local record checks and applicable actual-host behavioral scenarios; do not promote local test PASS into host qualification.
7. Record the adoption decision/effective scope separately. Merge, push, publication, release acceptance and production activation retain their own grants.

Optional skills stay outside auto-discovery until explicitly selected and qualified. The standards catalog remains informative until a competent applicability/adoption decision.
