# Assurance profiles

Profiles select proportional evidence and process depth, not model intelligence, permissions or a separate rule universe. STANDARD is the default. Provider and host choice are orthogonal to profiles.

| Profile | Eligibility | Minimum operating record | Extra assurance |
|---|---|---|---|
| LITE | Small reversible local work; classified non-sensitive data; no production, irreversible/external mutation or required independent gate | Short request, known facts/grant, focused evidence and checkpoint | Only applicable boundaries; preserve all invariants |
| STANDARD | Ordinary software delivery with understood scope | Project/host contract, request/state/evidence, impact-based checks | Actual instruction loading and relevant tool-route qualification |
| CONTROLLED | Sensitive data, production/privilege boundary, destructive/irreversible or high-impact external effects, applicable independent requirement | Full impact/authority/qualification records for affected scope | Protected approvals, recovery evidence and required independent acceptance |

Unknown classification prevents LITE eligibility. It does not force a production action under CONTROLLED before authority exists. A project may retain STANDARD generally and apply CONTROLLED to a specific release or data operation. Document the scoped profile decision.

Common obligations: truthful evidence, protected data, valid authority, preservation, non-gaming, traceability and safe continuation. No profile authorizes an effect or waives these. Existing approved external obligations are assessed by competent owners, not inferred from a project label.
