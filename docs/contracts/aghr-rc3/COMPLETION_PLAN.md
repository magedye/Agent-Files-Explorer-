# استكمال عقود المرحلة 0 — نطاق التنفيذ

**التفويض:** طلب المالك 2026-10-22: استكمال العقود قبل قالب SEC-001. مصدر المتطلبات هو مرجع rc.3 ومواصفة Studio المعتمدان؛ التنفيذ على شجرة العمل الحالية مع حفظ العمل السابق.

## القبول قبل التعديل

1. تغطية جميع عمليات Studio §§27–36، بما فيها قناة WebSocket، بمداخل ومخرجات وأخطاء ومصادقة واضحة؛ جرد آلي يقارن التغطية بالنص المعتمد.
2. مخططات JSON Schema 2020-12 للـmanifest والبنود والمهارات والتأهيل والحالة والأدلة والإعدادات وعقد المحرك وكل أنواع API، مع أمثلة قبول ورفض.
3. صيغة JSONL محددة واختبار تعدد السطور والحفاظ على بايتات المصدر والتكرار والتعارض؛ إقرار المضيف مستقل عن التنفيذ؛ تعريف هوية الفاعل والثقة خارج بيانات الطلب.
4. ربط الموافقات ببصمة المقترح، وCI وحده ناشر الحالة، وحدود الموارد وحالات الغياب والإلغاء والتجاوز صريحة. JSON Schema لا يحل محل فحوص السياسة في محرك Python.
5. تطابق SQL مع المصدر وإنشاء جداول SQLite الاثني عشر في الذاكرة، مع بقاء الهجرة الدائمة غير مشغلة.
6. فحوص العقود، `npm test`، وصحة السياق وفرق الملفات؛ حفظ المواصفات والمرجع والمرشح والمدخلات السابقة ببصماتها.

## الدفعات

| الدفعة | العمل | دليلها |
| --- | --- | --- |
| A | إكمال مخططات الحزمة والبند والمهارة والتأهيل والحالة | حالات موجبة وسالبة، دون قالب SEC-001 |
| B | جرد العمليات، أنواع API وOpenAPI كامل، إعدادات وعقد محرك محدد | تطابق الطرق والمسارات، كل جسم/جواب له نوع، لا مرشح لغة، حماية الأفعال بالبصمة |
| C | تثبيت قرارات الأدلة والثقة والمحولات وعقد التسلسل | اختبارات JSONL وأمثلة نقل موثقة، مع منع الاستدلال على النجاح من البنية |
| D | ربط C1–C12 بفحوص البنية وبوابات المحرك، مراجعة ذاتية وحفظ الدفعة | إيصال قبل/بعد وسجلات تحقق وحالة استئناف دقيقة |

**حد الاكتمال:** اكتمال العقود القابلة للمراجعة لا يساوي اجتياز المرحلة 0. تبقى واجهات HTTP والعرض للقراءة فقط وsentinel والمحرك والمضيف وتأهيل الموارد بوابات تنفيذية مستقلة. لا يبدأ قالب SEC-001 أو الترحيل الجماعي ضمن هذا الطلب.

**موضع الاستلام:** اكتمل تعريف الدفعات A–D في contract.1؛ نتائج الفحص الفعلية والنسخ السابقة في إيصال الاستكمال. الخطوة التالية تنفيذ بوابات المرحلة 0، وليست إعادة جرد البنود أو بدء SEC-001 مباشرة.
