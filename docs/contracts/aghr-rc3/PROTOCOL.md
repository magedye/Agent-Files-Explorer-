# بروتوكول التنفيذ — contract.1

**النطاق:** تعريف العقود التابعة لمرجع rc.3 ومواصفة Studio. الإصدار `contract.1` يخص واجهات التنفيذ، و`schemaVersion: 1.2` يخص بيانات AGHR. لا يمثل أي منهما إصدار تطبيق منشورًا أو اعتمادًا جديدًا للحزمة.

## 1. البيانات والمصدر

- النصوص والملفات المملوكة للحزمة UTF-8. يحفظ الاستيراد الأجنبي بايتاته الأصلية وبصمتها؛ يمكن عرض النص غير السليم باستبدال محارف فك الترميز مع تشخيص، ولا يعتمد بوصفه دليلًا صالحًا.
- `source_hash` بصمة البايتات الفعلية، لا النص المعاد تنسيقه. `source_line` رقم السطر الأصلي بدءًا من 1. مسارات المصدر لا تمنح حق الوصول؛ يفحص الخادم الجذر والمسار والروابط قبل فتحه.
- مخططات `item` و`capability` تفصل المصدر والوظيفة والقوة والسلطة والنطاق والإنفاذ. وجود الملف لا يثبت إتاحته للجلسة أو تأهيله.
- `skillQualification` يحتفظ بصيغة السجل الواحد في المثال المرجعي، ويقبل قائمة غير فارغة عند تعدد المهارات/المضيفين. القارئ ينتج قائمة داخلية ويحتفظ بالأصل. يغطي المحرك جميع `scope.skillIds` ويمنع تعارض سجلات المفتاح الواحد؛ `uniqueItems` وحده لا يثبت ذلك.
- سجل التأهيل يربط `host` و`hostVersion` و`scope` و`contentHash`. في SQL تقابلها `host` و`host_version` و`scope` و`content_hash`؛ الهوية لا تختزل إلى المضيف والإصدار. تغيير أي مفتاح ينتج تركيبة جديدة `NOT_RUN` مع إبقاء السابقة للتاريخ.
- `EXCEPTION` يحتاج `expiresOn` ومرجعًا، و`repo-measured` يحتاج بيانات المعايرة. صلاحية قياس الأثر وموافقته وروابط تشغيله يفحصها المحرك، ولا تُستنتج من صحة JSON.
- `ItemView` يعرض المصدر غير الصالح أيضًا، مع `item: null` وتشخيصه؛ لا يسقطه من الجرد أو يعرضه كسياسة مقبولة. غياب الترجمة شارة، ولا تدخل اللغة في اختبار الانطباق.

## 2. JSONL والإقرار والتنفيذ

[EVIDENCE_FORMAT.json](EVIDENCE_FORMAT.json) يحدد الصيغة: غلاف المهمة/الجلسة نفسه، وحدث واحد في `events` لكل سطر. تكتب السجلات الجديدة بصيغة JSON حتمية وفق [RFC 8785](https://datatracker.ietf.org/doc/html/rfc8785)، ثم LF. يقبل القارئ LF أو CRLF ونهاية اختيارية للسطر الأخير، ويحفظ الأصل كاملًا.

الحدود الافتراضية: 16 MiB للملف، و1 MiB للسطر، و10,000 سجل. يحد المستدعي القراءة قبل تحميل الملف؛ المرجع البرمجي يعمل على Buffer محدد أصلًا. تتطلب زيادة الحدود قرار إعداد مخولًا.

| الحالة | التصرف |
| --- | --- |
| عدة أحداث في السطر | رفض شكل السجل، دون تفجيرها إلى صفوف تتنافس على مفتاح SQL نفسه |
| تكرار سجل أو تعارض المهمة/هوية الجلسة | تشخيص ورفض استيراد الملف كدليل مقبول؛ الجزء المقروء للتشخيص فقط |
| `ended_at` غير معروف ثم معلوم | يسمح بإضافته؛ لا يسمح بتغيير وقت نهاية معلوم إلى قيمة أخرى |
| JSON أجنبي غير حتمي أو يحمل مفاتيح مكررة | `UNSUPPORTED_SERIALIZATION` مع حفظ الأصل؛ تحويله المقترح يمر بالمراجعة، ولا يعاد كتابة الأصل تلقائيًا |
| UTF-8 تالف، BOM، YAML أو سطر فارغ | تشخيص صريح؛ لا تحوّل النتيجة إلى عدم تطابق مهارة أو نجاح |
| `host.acknowledged` | إقرار خام بالمهمة والمضيف من غلاف الجلسة؛ لا يحمل حالة تنفيذ أو تحقق |
| `host.signal` مع `HOST_SIGNAL` | يحتاج الإقرار و`execution_ref` للمهمة نفسها؛ يفحص المحرك صدق المصدر والارتباط، عملًا بالشرط الأشد في §14.2 |
| لا إشارة مستقلة للمضيف | `NOT_OBSERVABLE` مع السبب؛ لا تمنع متابعة التنفيذ المخول إذا توفرت أدلته المستقلة |

المحوّل المرجعي في `tools/contracts/evidence_jsonl.mjs` يثبت التسلسل محليًا فقط؛ يرجع `schema_status: NOT_RUN` و`trust_status: UNKNOWN`. يفحص المدقق العام البنية بعد ذلك؛ يفحص محرك Python حالات المهارة والمخرجات ومعايير المهمة والثقة. لا يحقق نجاح محلل JSON أي انتقال إلى `EXECUTED` أو `VERIFIED`.

## 3. هوية الفاعل والثقة

`X-Studio-Token` اعتماد مؤقت يدور عند البدء، ويربطه الخادم بفاعل مسجل عبر تهيئة موثوقة. قائمة ربط فارغة تعني رفض الصلاحيات. لا يستمد الخادم الفاعل أو الدور من جسم الطلب أو معاينة الواجهة. `authority.level` مستوى البند المعلن؛ يبقى التحقق من مُصدره مستقلًا، مع بقاء هرم تعليمات المضيف والمالك نافذًا.

`auth.schema.json` عقد داخلي لسياق ينشئه الخادم. حقل `role` في طلب الموافقة يحدد خانة المراجعة المطلوبة. يثبت الخادم الدور الفعلي والنطاق والفاعل من الربط الموثوق، ويسجل `simulated_role` بصورة منفصلة. بيانات `publisher: ci` أو `source: host` لا تصدق نفسها؛ المصدر غير المثبت يبقى `UNKNOWN`.

| سياسة العملية في الفهرس | الفحص المطلوب على الخادم |
| --- | --- |
| `read` | صلاحية القراءة ضمن مساحة العمل/المشروع المسجلين |
| `installation_owner` | إثبات مالك التثبيت من قناة محلية موثوقة؛ دور المعاينة أو اسم governance-owner لا يمنح هذا الإثبات |
| `registered_source_read` | المصدر مسجل ومسموح، والقراءة لا تغيّر بايتاته؛ الفهرس مشتق وفي الذاكرة في العرض الأول |
| `cp_create` / `cp_edit` | `cp.create`؛ أو `cp.edit_own` مع مطابقة المنشئ الفعلي، أو `cp.edit_any` |
| `verify_fast` / `verify_command` / `cp_edit_and_verify` | صلاحية التحقق المناسبة لكل أمر، وصلاحية تعديل المقترح عند اللزوم. fast: validate/lint/generate/check/doctor؛ eval/qualify يحتاجان صلاحية التحقق الكاملة وضوابط الموارد المؤهلة |
| `approval_slot` | صلاحية خانة الموافقة المحددة، والفحوص والموافقات المطلوبة وبصمة المقترح الحالية |
| `approved_cp_scoped_grant` | حزمة approved بلا حواجز، وكل الموافقات والفحوص تطابق البصمة، وتفويض محدد للمشروع والفعل والأثر |
| `adoption_preview` / `adoption_apply` | صلاحية المعاينة؛ وللتطبيق صلاحية adoption.apply والتفويض المحدد وبوابات CP. الأثر patch/commit، ونشر state يبقى لـCI |
| `run_owner_or_governance_owner` | منشئ التشغيل الموثق أو مالك الحوكمة المخول؛ لا يقبل منشئًا يحدده الجسم |
| `verified_ci_merge` | دليل دمج موثوق يطابق المرشح والتصدير، قبل إغلاق الحزمة |
| `scoped_external_write` | تفويض صريح للعملية الخارجية المحددة؛ إعداد مسودة/مرفقات محلية لا يثبت إرسالها أو قبولها لدى CI |

يفحص التفويض والبصمة مجددًا قبل الأثر، ويُسجل الفاعل الحقيقي. المخططات لا تنفذ هذه السياسات في Node؛ المسؤولية لمحرك الحوكمة وجسر التفويض الخادمي الموثوق.

## 4. النقل وسير التغيير

المصدر القابل للتحرير للعمليات هو [API_OPERATIONS.json](API_OPERATIONS.json). ينتج المجمّع [openapi.json](openapi.json) ومخطط الأجوبة. الصيغة المثبتة [OpenAPI 3.1.0](https://spec.openapis.org/oas/v3.1.0.html). توجد 58 عملية من §§27–36، وإضافة واحدة: `POST /workspaces/{id}/cps/{cp_id}/submit` لتنفيذ خطوة إرسال المقترح validated إلى in_review الواردة في §37 والخريطة B.

- جميع مداخل البيانات لها نوع؛ لا يقبل الجسم حين تصرح العملية `x-request-body: forbidden`. ترفض معاملات الاستعلام غير المعلنة، ومنها `language`.
- `limit/cursor` امتداد نقل للقوائم: الافتراضي 100، أو 20 لسجل الاستخدام، والحد 500؛ لا يمثل حد الصفحة اكتمال الجرد. `meta.total` و`next_cursor` يتيحان استكماله. يجب تقديم المسار الثابت `capabilities/matrix` على مسار المعرف في المحول.
- الأجوبة `{data, meta}`؛ أجوبة النجاح البنيوي لا تحمل `meta.error`. أخطاء الاستعلام/التفويض/التعارض لها غلاف خطأ. نتيجة تشغيل فاشل داخل GET run تظل نتيجة تشغيل فاشل ولو نجح طلب القراءة HTTP.
- عمليات الأثر المرتبطة بمقترح أو محتوى تتطلب `If-Match` ببصمة SHA-256 مقتبسة كما أعادها الخادم. الغياب 428، وعدم التطابق 412. يمنع الطلب القديم حتى لو كانت صلاحيته صحيحة.
- بصمة المقترح: `sha256:` متبوعة بـSHA-256 للبايتات UTF-8 الناتجة من JCS لكائن ثابت الحقول: `base_package_version`, `base_candidate_hash`, `title`, `kind`, `target_item_id`, `source`, `proposed_yaml`. الحقول الغائبة المسموح بها تمثل `null`. تبقى محارف YAML الأصلية، بما فيها CRLF، داخل السلسلة دون تطبيع. توليد هذه البصمة والتحقق منها في المنتج من مهام المحرك المثبت؛ المحوّل المحلي ليس إثبات تأهيل Python/CI.
- تعديل المقترح يبطل الموافقات والفحوص والمعاينات المرتبطة بالبصمة السابقة ذريًا، ويحفظ سبب ووقت القرار الأصليين في التاريخ. قبل التصدير يعاد فحص البصمة والتفويض والفحوص.
- أنواع CP الثلاثة `calibration / PROJECT_SELECTION / GENERATED_FILE` تخص غلاف العمل. لا تضاف إلى أنواع بنود الحوكمة الثلاثة عشر. يفحص المحرك `proposed_yaml` بالمخطط المناسب بعد تحليل YAML؛ حفظ مسودة لا ينشر بندًا غير متحقق منه.
- `submit` لا يوافق على الحزمة؛ و`close` لا يثبت الدمج من حقل يرسله العميل. لا يعبر أي منهما إلى الحالة المنشورة دون دليل المسار الصحيح.
- إقرارات compress/compact المرسلة تحمل المرحلة والسبب فقط؛ يضيف الخادم الفاعل والدور والبصمة. compact يحتاج governance-owner وlookup مؤهلًا. PRIN-007 عند L1+ وحفظ P0 والميزانية شروط على النسخ والتحميل والتصدير كلها.
- أي اختلاف معروف بين Studio وCI لنفس المرشح والمحرك والمدخلات والإعدادات يمنع التصدير المعتمد والنشر. غياب نتيجة CI هو `NOT_RUN`؛ إعداد draft patch/PR المخول لا يصبح قبول إصدار.

### WebSocket

الترقية HTTP تعيد 101 بلا جسم JSON؛ الرسائل التالية لها غلاف JSON ومخطط `StreamFrame` وتسلسل متزايد يحفظ stdout/stderr. تظل مصادقة `X-Studio-Token` مطلوبة. [واجهة WebSocket في WHATWG](https://websockets.spec.whatwg.org/) لا توفر وسيطًا لتعيين هذا الرأس من constructor المتصفح؛ العميل الذي لا يستطيع إرساله يعرض `NOT_SUPPORTED` لهذا النقل ويستخدم GET run الموثق للمراقبة. لا ينقل التوكن إلى URL أو يسقط المصادقة. تأهيل هذا النقل في المضيف منفصل عن صحة مخطط الرسالة.

## 5. المحرك والموارد والإعدادات

`engine.schema.json` يميز NOT_CONFIGURED وPINNED وQUALIFIED وFAILED. أولها هو الوضع الفعلي في القالب. يلزم الإصدار والبصمة والتوزيع وschema 1.2 قبل ادعاء الربط؛ التأهيل يحتاج دليلًا مستقلًا، والتحقق من توقيع الحزمة مطلوب قبل التوليد المقبول. لا تستخدم نسخة 1.2.0/1.3.0 القديمة بديلًا تلقائيًا عن CLI rc.3، ولا تثبّت اسم حزمة خارجيًا من المثال.

المحرك المثبت هو مصدر validate/lint/generate/check/eval/qualify/doctor. الجسر يستخدم أمرًا مسموحًا وargv منظمة و`shell:false` وجذرًا وبيئة مخولين. لا تُفسّر الأعلام كأمر shell أو كمنح صلاحية. إصدار تعريف العقد لا يمنح تنفيذًا بهذه الأدوات.

eval: ‏600,000 ms و2048 MiB؛ qualify: ‏3,600,000 ms و2048 MiB. غياب محول مؤهل للزمن والذاكرة وشجرة العمليات يمنع التنفيذ المطلوب. يسجل التجاوز `resource_limit_exceeded` وسبب timeout/memory_limit والمخرجات الجزئية؛ الإلغاء المستخدم يسجل errored مع `user_cancelled`، ولا يدعي تجاوزًا لم يقع. القياسات غير المرصودة null، وليست صفرًا مصطنعًا.

قالب `settings.yaml` يستخدم JSON، وهي صيغة صالحة ضمن YAML 1.2، حتى يفحص محليًا دون إضافة parser آخر أو نسخة إعداد موازية. دعم YAML الأوسع وتأهيل محوله من بوابات المحرك. إعداداته ذاكرة فقط، بلا توكن أو ربط مستخدم أو مفتاح خاص أو مسار تنفيذي مخمن. وضع التخزين الدائم يحتاج تفويضه الخاص؛ وجود `authorization_ref` في الملف لا يثبت التفويض.

## 6. الإسقاطات والحفظ

SQLite يتبع كتل المصدر الست دون تعديل. المشتقات لا تستبدل ملفات المصدر أو الأدلة. حقل eval في CP يجمع التشغيل المرتبط عبر `verification_runs.linked_package_id`؛ لا يحتاج حقل SQL متنافسًا. adoption عرض لسير CP من نوع GENERATED_FILE مع بيانات المشروع، ويستخدم معرف CP نفسه؛ لا يضاف جدول ثالث عشر. تبقى بيانات الغلاف في المقترح المنظم، والفحوص والفرق والموافقة في مواضعها المحددة.

[MIGRATIONS.json](MIGRATIONS.json) يثبت checksum وإصدار الهجرة الأولى. تطبق كمعاملة ذرية مع foreign_keys، ويحدّث `PRAGMA user_version` بعد النجاح؛ الفشل يعيد ROLLBACK. الفحص الحالي في الذاكرة فقط. تشغيل ذلك على قرص دائم لا يجيزه عقد أو قفل ملفات.

القيم grouped في metrics والـraw stdout/stderr/output ومصدر YAML محفوظة. المقاييس بلا ملاحظة تعرض NOT_RUN وقيمة null. الحقول الرقمية إسقاطات للأصل، وليست بديلًا عن الدليل. `state.json` مصدر للقراءة في Studio؛ ناشره CI بعد التحقق والدمج وحده.
