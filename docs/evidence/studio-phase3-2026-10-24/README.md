## المحاولة الأصلية الوحيدة

`NATIVE_SINGLE_ATTEMPT.json`: تشغيل Codex app-server stdio حقيقي داخل مشروع مؤقت تحت T15: انتظار initialize لمدة20 ثانية، دون استجابة أو stderr. زمن المراقب22.641 ثانية، حد30 ثانية/2GiB، وإثبات إغلاق شجرة العمليات (`active_processes_after=0`). نجاح المراقب exit0 يعني إكمال التشخيص فقط؛ المضيف نفسه `initialized=false / ENVIRONMENT_BLOCKED / qualification=NOT_RUN`. السبب الأعمق غير مثبت.

غياب قناة agy مأخوذ من الرصد السابق المقبول؛ لم تُجر محاولة تثبيت أو محاولة تشخيص ثانية. وجود سطح مكتب Antigravity لا يثبت قناة تشغيل مهارات. لا قراءة لمحادثات المالك أو استخراج بيانات اعتماد. البروتوكول المستخدم مستمد من [مرجع App Server الرسمي](https://learn.chatgpt.com/docs/app-server).

## T22 وT23

- مصدر التشغيل `server/studio/skills/`، والواجهة `src/features/skills/`. تهيئة المهارات تأتي من المشغل المحلي عبر `--skill-config=<absolute-json>`، وليست أسماء ملفات تنفيذ يرسلها HTTP. الخادم لا يمثل المضيف المحلي على أنه Codex.
- كل تشغيل يحتاج هوية جلسة ومنحة أحادية الاستخدام مقيدة بالمهمة والعملية والبصمة والمدة، وموافقة المشغل المحلي. إعادة التشغيل/اختلاف المحتوى أو المرحلة/تكرار المنحة لا يتجاوز الحارس. الرفض دون منحة403 ومدقق.
- اختيار/تحميل التعليمات لا ينتج EXECUTED أو VERIFIED. معايير القبول الفعلية ملزمة، والفشل يبقى failed في التاريخ. التأهيل المحلي استند إلى3 تنفيذات فعلية، ويرتبط بالمضيف ونسخته والنطاق وبصمات التعليمات/المشغل/المحرك وتاريخ التأهيل.
- التاريخ محفوظ في الجداول الاثني عشر القائمة، موسوم `HISTORICAL_ONLY`، ولا يعيد إنشاء أدلة حية بعد إعادة التشغيل. الانطباع عن النتيجة لا يتحول إلى موافقة CP أو تأهيل أصلي.
- شاشات السيناريوهات مترجمة، وتظهر الحالات الثلاث للاكتشاف والحجب بصورة مستقلة. مصدر8+7 هو دليل E4 المحلي المقبول والمثبت ببصمته؛ لم يعاد وصفه بأنه اختبار للمضيفين.
- الأدلة: `final-local-v2/SKILL_HTTP_ACCEPTANCE.json`، و`SKILLS_FOCUSED_4.log`:11/11. دليل المتصفح النهائي في `browser-final-v2/`؛ النسخ الأقدم محفوظة.

## T24: مسار الأدلة والنشر

1. يختار المستخدم معرف دليل موجودًا في مشروع مسجل. العملية المفوضة تقرأ الأصل وتتحقق من ثباته، وتشغل E2 الحقيقي؛ تعيد ملفين قابلين للتنزيل: `.aghr/runtime_evidence/{task_id}.jsonl` بنفس البايتات، و`.aghr/ci-submissions/{task_id}.json` ببصمته ونتيجة CLI3 الخام. الحالة **PREPARED_NOT_SUBMITTED**: لا إنشاء PR أو إرسال إلى GitHub من الواجهة.
2. فحص PR يقرأ الملفين من API عند SHA المحدد، ويتحقق من Git blob SHA1 وSHA256 والحجم والمسار ووجود الملفات ضمن تغيرات PR. لا تحميل من URL يقدمه الملف. لا صلاحية كتابة أو OIDC في مهمة PR.
3. يمر الأصل عبر schemas في Python، ثم نسخة مطابقة مؤقتة إلى **E4 غير المعدل**. الادعاءات المستوردة تبقى `producer_authentication=NOT_ESTABLISHED / execution_status=NOT_OBSERVABLE`. دليل المحاكاة مرفوض؛ لا تحويل لادعاء PASS/VERIFIED أو `source:ci` إلى إثبات تنفيذ.
4. يعاد تشغيل `validate --strict` عبر E2 المثبت وT15. تطابق الحكم وحده لا يكفي: يقارن المحرك وبصمة المرشح والمدخلات والإعدادات والأحكام والتشخيصات. أي `STUDIO_CI_DIVERGENCE` يوقف المسار.
5. الناشر يحصل على رمز OIDC من قناة GitHub الرسمية، ويتحقق من توقيع RS256 ومفاتيح الجهة الرسمية، والمدة والجمهور ومعرفي المستودع والمالك والفرع وملف workflow وSHA وسياق push. كائن JSON أو رمز اختبار أو Studio Grant لا ينشئ capability نشر.
6. يتأكد من PR مدمج فعليًا، وأن merge SHA يساوي SHA تشغيل CI ورأس main الحالي. ثم ينشئ Git commit لا يغير إلا `.aghr/state.json`، ويربطه بدمج PR، ويحدث المرجع بـ`force:false`. تقدم رأس الفرع أو انتهاء الهوية يمنع الأثر.

المسار الحالي يدعم **L0/NOT_RUN فقط**: لا eval PASS أو تأهيل مهارة أو إعفاءات مخترعة. يرفض تخفيض حالة سابقة مؤهلة؛ تحديثها يتطلب ملف نشر مؤهل لاحقًا. هذا حد وظيفي معلن، وليس إنجازًا للتأهيل الأصلي. إعداد الناشر في `.github/aghr-publisher-policy.json` مربوط بمعرفات المستودع المرصودة، وليس بادعاء `publisher:ci`. حماية main غير مفعلة في الرصد الحالي وليست شرطًا مُفعّلًا في هذا الملف؛ هوية النشر الموقعة وربط الدمج إلزاميان.

الكود: `server/studio/ci/`، `tools/phase3/ci.mjs`، `.github/workflows/aghr-phase3.yml`. تثبيت تبعيات Python من lock ذي بصمات؛ actions مثبتة إلى SHAs رُصدت من GitHub. لا تعديل لإعدادات المستودع أو الأسرار.

المرجع الرسمي لآلية الهوية: [GitHub OIDC](https://docs.github.com/en/actions/reference/security/oidc)، ولأحداث الفرع: [Workflow events](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows)، ولتحديث المرجع: [Git refs API](https://docs.github.com/en/rest/git/refs). نجاح تشفير متجه اختبار محلي لا يعني حصوله على هوية GitHub؛ ذلك مثبت باختبار رفض capability.

## الفروق والحفظ

| قبل | بعد |
| --- | --- |
| T20/T21 بلا شاشة تشغيل دورة المهارة | ربط محرك E4 الحالي بواجهة مهام وبطاقة ذات ثلاثة محاور |
| لا تجهيز لمرفقات أدلة PR | ملفات أصلية وبصمات وتقرير محرك، بمنحة ودون إرسال خارجي |
| لا ناشر post-merge | ناشر منفصل موثق الهوية والمصدر والدمج، بحارس تعارض الرأس ومسار كتابة واحد |
| نجاح محلي قد يلتبس على القارئ بنجاح مضيف | نتائج النواة المحلية منفصلة عن أعمدة native NOT_RUN وتأهيل المهارة الفعلي |

`before/` يحفظ بايتات الملفات الثمانية القائمة قبل التغيير. `BEFORE_AFTER.json` و`CHANGES.patch` و`after-final/` يحفظون الفرق والنسخة اللاحقة. `PRESERVATION.json` يتحقق من قوائم الحفظ المعتمدة مباشرة، دون اجتياز مجلدات الحوكمة؛ المرجع1.2.0 ومحركات E1–E4 والعقود محفوظة. `CUSTODY.lock.json` ختم SHA256 للبايتات وليس توقيع مالك أو هوية ناشر.

الفشل التجريبي محفوظ: SKILLS_FOCUSED_2 اختبر مصدرًا أفسده بتكرار السجل فكان الرفض422 صحيحًا؛ استبدل بمصدر متغير صالح لاختبار412. المحاولة3 اصطدمت بملف دليل قائم (EEXIST)، فحُفظت واستُخدم مسار جديد. browser-final لم يركز الحقل قبل Tab؛ صُحح إعداد الاختبار، دون تغيير المنتج لتجاوز الفحص. وصُحح عيب حقيقي في تاريخ دورة المهارة كي لا يسجل معايير قبول فاشلة بوصفها passed، مع اختبار رجعي.

## الخطوة غير المنفذة

مراجعة مخرجات هذا التسليم ونشر workflow ثم PR أدلة حقيقي ودمجه لتسجيل تشغيل GitHub وتحديث الحالة. لم تُنشأ PR أو commit/push في هذه المهمة. تأهيل المضيفين يحتاج قناة أصلية متاحة وتفويضًا لاحقًا لمحاولة جديدة؛ حد المحاولة الواحدة استُنفد. لا بداية تلقائية لـPhase4، ولا ترقية مرجع أو تطبيق patch على1.2.0.
