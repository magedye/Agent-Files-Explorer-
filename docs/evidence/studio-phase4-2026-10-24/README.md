# Phase4 — T25–T29، حوكمة وتعلم في بيئة Draft

## التفويض والنطاق

اعتمد المالك إغلاق Phase3 ضمن حدود native/hosted NOT_RUN الموثقة، وفوض تنفيذ T25–T29. هذه إضافة مستقلة تستخدم Python وE2/E3/E4/E5 غير المعدلة، وسجل CP وSQLite الاثني عشر جدولًا والمنح والتدقيق القائمة. لا مصدر أو مرجع يُعدّل، ولا تثبيت مهارة أو نشر حالة أو دمج تلقائي. موافقة CP في هذا الملف تخص **مسودة**، ولا تمنح صلاحية تطبيقها على مرجع أو مشروع.

## دليل منع الترقية التلقائية

- المراقب يقرأ الأصل ويحتفظ ببايتاته في CP؛ لا يحمّله كتعليمات ولا ينفذه. اختُبر YAML يتضمن وسم تنفيذ عدائي، وبقي نصًا غير منفذ.
- الدرس لا يصبح بندًا حاكمًا؛ التصنيفات غير المحسومة تبقى UNRESOLVED، والسبب غير المثبت UNPROVEN. المصدر المستورد ليس شهادة تنفيذ أو إثبات سببي.
- كل إنشاء/تقدم/إرسال/مراجعة يحتاج session ومنحة أحادية الاستخدام مرتبطة بالعملية والمورد والبصمة والمدة. الرفض403 مدقق، والهوية/الدور من الخادم.
- المقترح والبيانات المرتبطة به يثبتان بتطبيع JCS/SHA256 في Python. تغيرهما يحفظ القرارات السابقة في approval_history ويبطل المنح القديمة.
- لا endpoint يكتب السياسة أو state أو يثبت مهارة. `approved` هنا قرار مسودة؛ لا تصدير أو ترقية ضمن Phase4.

## دليل المعايرة

1. يختار المستخدم بندًا موجودًا بدليل assumed، ويذكر سبب القياس. لا يرسل PASS أو metrics أو executable.
2. يستدعي الخادم مقيّمًا **مسجلًا من المشغل** عبر E4. كل تنفيذ تحت T15: eval600s، qualify3600s،2GiB؛ أوامر الفحص تحت30s. لا تعديل لهذه الحدود.
3. البيانات المرسلة للمقيّم تتضمن run_id وitem_id وsource_hash وscope والسبب. يتحقق الخادم من إعادتها وتطابق القياسات في3 تنفيذات فعلية.
4. يحسب الدلتا من `after_metric - before_metric`؛ يتطلب repo_hash. لا يقبل قيمة يدعيها العميل أو تشغيلًا فاشلًا أو أجنبيًا أو قديمًا أو تابعًا لمحتوى مهارة تغير.
5. Python وحده يصوغ impact.evidence=repo-measured وlastCalibrated من وقت التنفيذ وmeasuredDelta؛ يظل ذلك داخل proposed_yaml في CP.
6. يلزم إرسال CP ثم موافقة governance-owner على البصمة الحالية. القياس وحده لا يعتمد المقترح. لا تكتب هذه العملية إلى الملف المرجعي.
7. حارس إضافي يمنع الالتفاف عبر تحرير بند عادي في الواجهة القديمة أو إنشاء wrapper calibration دون الدليل الحي. النص يفسره Python؛ ليس البحث عن سلسلة في Node.

الاختبار الإيجابي يقرأ فعليًا نسختي إعداد مشروع اختبار معزول: default_package قبل/بعد، ويحسب عدد حالات المطابقة وبصمة البايتات. لا تُعرض نتيجته بوصفها دليلًا على أثر سياسة أخرى أو المشروع الإنتاجي.

## التشغيل والتهيئة الموثوقة

يشغل الخادم المعتاد عبر `server/studio/serve-draft.mjs`، مع مجلد Draft منفصل وPython مثبت. يقبل خيار `--phase4-config=<absolute-json>`:

```json
{
  "intakeRoot": "D:/path/to/registered/INBOX",
  "measurementSkillId": "registered-project-measurement",
  "metaSkillId": "registered-candidate-evaluator",
  "requiredBehavioralEvals": ["actual-project-eval-id"]
}
```

هذا مثال إعداد، لا دليل على تسجيل هذه المهارات. معرّفات المقيمين تشير إلى read-only drivers في `--skill-config` الموثوق؛ لا يختار HTTP ملفات التنفيذ أو المسارات. يفعّل المراقب بعد التسجيل بمنحة من الواجهة. لا يفعل الإعداد وحده watcher أو يمنح الموافقة.

مقيّم القياس يعيد binding كما تلقاه وvalid وbefore_metric وafter_metric وrepo_hash من قياسه الحقيقي. مقيّم الحزمة يعيد نتائج جميع المعرفات المسجلة وgeneration_check للمرشح المرتبط ببصمة CP. لا يكفي ذلك كـJSON مستورد؛ يتطلب تنفيذ E4 حيًا وإيصالاته. Python يعيد أيضًا فحص قواعد السياسات المقترحة بـE2، فلا تتجاوز نتيجة مقيّم قواعد السلطة أو المصدر. لا تنفيذ للأدوات المقترحة في مرحلة التأليف.

افتراضيًا، غياب هذه التهيئة **يحجب** المعايرة والموافقة على تغيير الحزمة؛ لا ينشئ نتائج ناجحة. تحديد مقيّم إنتاجي ومعنى قياس المشروع قرار تشغيل موثوق لاحق، وليس قيمة خُمّنت من الوارد.

## الأدلة

- `final/HTTP_ACCEPTANCE.json` و`FOCUSED_FINAL.log`: نواة8/8، بما فيها الخطوات السبع والتأهيل الفعلي والدلتا والموافقات وإبطالها ورفض التأهيل القديم.
- `FINAL_CONTRACT_ACCEPTANCE_V2.json` و`CONTRACTS_FINAL_V2.log`: رفض السبب المزعوم، حفظ عقد API القديم،403 للمسارات غير المفوضة، ورفض تجاوز المعايرة من التحرير العام.
- `full-suite-final/HTTP_ACCEPTANCE.json` و`NPM_TEST_FINAL.log`: نتائج الانحدار النهائية على النسخة الثابتة، بالعدد الفعلي في `VERIFICATION.json`.
- `browser-final/`: Edge حقيقي، سياق مستقل، المسارات الخمسة و7 خطوات وتأهيل وeval حقيقيان، العربية/الإنجليزية وأربعة عروض، وSentinel. القياس في مشروع الاختبار المحلي فقط. فحوص الحارسين النهائيين الخلفيين موثقة باختبار العقد والانحدار النهائي؛ لم تتغير واجهة المتصفح بعدها.
- `TESTED_SOURCE_FINAL.json`: نسخة الملفات الخاضعة للانحدار النهائي؛ `PRESERVATION.json`: حفظ المرجع والمحركات وملفات المراحل السابقة بقوائمها الصريحة.
- `before/` و`after-final/` و`BEFORE_AFTER.json` و`CHANGES.patch`: البايتات والفروق. `CUSTODY.lock.json` ختم SHA256 تقني، وليس توقيع مالك أو قبول إصدار.

## المحاولات السابقة وتصنيفها

الفحص الأول رفض CAPABILITY في بيانات الاختبار لأنه افتقد skillQualification. صُحح الاختبار إلى NOT_RUN دون إضعاف العقد؛ الفحص الثاني والثالث8/8. في مراجعة الإغلاق أضيف منع الادعاء السببي غير المثبت، والحفاظ على API القديم، وحارس عدم تجاوز المعايرة. بدأ الانحدار الأول قبل تثبيت هذه الحراسة؛ رفضت بعض عملياته تبدل بصمة المحرك (`PHASE4_SOURCE_DRIFT`). حُفظ الرفض الفعلي من SQLite في `REGRESSION_FIRST_ROOT_CAUSE.json`، ولم يسجل نجاحًا. أعيد الانحدار على نسخة ثابتة؛ المحاولات القديمة محفوظة ولا تستبدل النتيجة النهائية.

## الحالة المتبقية

قبول المالك لـPhase3 محفوظ، ولا يحول native/hosted NOT_RUN إلى أدلة. لم تُجر محاولة جديدة للمضيفين أو نشر GitHub. لا قبول مستقل أو إصدار أو ترقية مرجع. التحقق الإيجابي لمقيّم meta إنتاجي والتشغيل على مشروع المالك ومقاييسه الفعلية لم يُنفذا؛ عند غيابهما تستمر البوابات في الحجب. لا بداية تلقائية لـT30 أو Phase5.
