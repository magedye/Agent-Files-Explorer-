## فحوص الصدق السبعة

لكل فحص حالة رفض وحالة قبول مقابلة؛ يفحص المحرك الدليل والمعايير قبل منح النجاح. تبدأ تجربة التحقق برفض التحميل دون تنفيذ، ثم تنتقل إلى التنفيذ الفعلي والمعايير الخاطئة فالصحيحة. لا استبدال للمحرك أو المزود أو المتحقق بـmock.

| الفحص | حالة النجاح الوهمي المرفوضة | الحالة السليمة |
| --- | --- | --- |
| H1 | LOADED أو تغيير JSON الجواب إلى VERIFIED، دون عملية | عملية فعلية، أثر دخل/خرج، ومعايير مستوفاة |
| H2 | معرف مهارة غير موجود: UNKNOWN_ID وexit1 | معرف مرصود في المضيف المحلي يمر بالاختيار، دون مساواته بـVERIFIED |
| H3 | برنامج فعلي يخرج 0 بلا أي محتوى | خرج فعلي غير فارغ قابل للتحقق |
| H4 | معيار يناقض الخرج الفعلي: verified=false وexit1 | المعايير الصحيحة نفسها تُستهلك وتنجح |
| H5 | مهارة تتطلب صلاحية غير ممنوحة: BLOCKED/توقف | عدم وجود مهارة مناسبة: NO_SKILL_MATCH/مسار مباشر مسموح |
| H6 | طلب HOST_SIGNAL بلا رصد، رغم وجود عملية | إقرار مضيف aghr-local-process ببدء Job فعلي مربوط بـPID/run/task؛ ليس إشارة Codex أو Antigravity |
| H7 | إصدار قديم أو تغيير محتوى SKILL بعد تأهيل فعلي: NOT_RUN | سجل حالي مدعوم بثلاث عمليات حقيقية ومطابق لجميع المفاتيح |

الخرج الخام السلبي المباشر من CLI:

```json
{"protocol_version":"3","command":"check","result":"INVALID","exit_code":1,"data":null,"diagnostics":[{"code":"E4_REJECTED","message":"EXECUTION_EVIDENCE_REQUIRED"}]}
```

المقتطف يحذف source فقط للاختصار؛ الأصل في [loaded-not-executed](cli/loaded-not-executed.stdout.json). الإيصالات المزورة في جسم الطلب ترفض مبكرًا برمز2؛ [الحالة](cli/forged-receipt.stdout.json).

## السيناريوهات الثمانية

1. تأليف دالة Python كأثر مسودة والتحقق من نحوها، ثم تمرير خرجها الحقيقي إلى مهارة مراجعة في مرحلة تالية.
2. طلب بسيط لا يحتاج مهارة: NO_SKILL_MATCH.
3. مهارتان متداخلتان: اختيار المفضلة دون تحميل البديلة.
4. SKILL موجود دون منفذ متاح للجلسة: NOT_OBSERVABLE.
5. صلاحية مفقودة: BLOCKED، دون fallback صامت.
6. عملية تفشل فعلًا: EXECUTED_FAILED، ولا VERIFIED.
7. طلب عربي ومحفز إنجليزي فقط: NO_SKILL_MATCH صريح؛ كما اختُبر المطابق العربي في b.
8. قراءة governed-learning من المرجع دون تعديله، وتشغيل إجراء محلي يستخرج درسًا من فشل فعلي: السبب UNPROVEN، التصنيف وطلب مراجعة المالك، وعدم ترقية سياسة. هذا ليس تفعيلًا أصليًا للمهارة على Codex.

## حدود الثقة والحالة

`e4-bridge.js` يحتفظ بإثباتات التنفيذ في ذاكرة خاصة؛ JSON المستورد أو التوكن المستنسخ لا يعيد إنشاءها. `entry.py` RPC داخلي يثق في المضيف الموثوق؛ لا يُعرض كواجهة عامة تقبل host/receipts من المستخدم. CLI العام لا يقبل تلك الحقول، وhost-config إعداد صريح من مشغل النظام لبرامج Python المقروءة فقط. لا مسارات HTTP جديدة أو تعديل لمحركات E1–E3.

نجاح النواة **ليس تأهيل Codex أو Antigravity**. إصدار Codex CLI `0.162.0-alpha.2` مرصود فقط؛ لا دليل تشغيل أصلي للمهارات عليه. لم يظهر Antigravity في PATH، ثم عُثر على ملفه التنفيذي بالمسار الافتراضي خارج PATH بإصدار `2.25.0.0`؛ لا توجد قناة رصد/تنفيذ مهارات أصلية مهيأة. طُلبت القناة من المالك. حالة فحوص كل مضيف الأصلي **REQUIRED / NOT_RUN / NOT_WAIVED**؛ لا نتيجة MOCK بديلة. ملف `NATIVE_HOST_OBSERVATIONS.json` هو الرصد الأحدث، ويستكمل ملاحظة PATH الأولية داخل تقرير الاختبار دون محوها.

التطبيق Draft؛ المرجع 1.2.0 والعقود وE1/E2/E3/E5 محفوظة. لم تُكتب قاعدة Draft الافتراضية أو state/runtime_evidence، ولم يطبق patch أو يُنشر إصدار. لا تُربط نتيجة JSON fixture المحلية تلقائيًا بمتطلبات P0 للبند المؤسسي SEC-001؛ يبقى المسار الأصلي BLOCKED/3 لمتطلباته الفعلية. T20–T24 والربط بالواجهة والنشر ليست منجزة من تنفيذ النواة وحده.

قبل/بعد الوثائق الخام في `before/` و`after/`؛ `BEFORE_AFTER.json` و`CHANGES.patch` للفرق، و`CUSTODY.lock.json` لختم البايتات. لا يُعد SHA توقيع مالك أو إثبات ناشر.
