# نطاق التنفيذ والقبول

1. T12: نسخة مستقلة owner-approved-mock داخل المرشح الحالي، تحفظ الأصل المقفل. تفعيل 44 سلطة للمحاكاة فقط ووسم OWNER_T12_OVERRIDE، مع SourceGrant موقّع بمفتاح اختبار Ed25519 مؤقت. المفتاح العام والإيصال مثبتان خارج النسخة؛ لا مفتاح خاص محفوظ.
2. اختبار CLI 3 معزول يستدعي E2 كما في T06؛ استبدال دليل E3 للقواعد الثلاث الموقعة فقط. validate --strict وlint يجب أن يخرجا VALID/0، وCLI الأصلي يبقى BLOCKED/3. تزوير التوقيع أو البصمة أو النطاق وفقد حقل إلزامي يجب أن يُرفض.
3. عند تحقق الشرط السابق يسجل قبول المالك المشروط: CLOSED_FOR_T12_OWNER_APPROVED_MOCK_ONLY. لا يساوي ذلك قبولاً إنتاجياً أو منحة حقيقية للـBackend.
4. T13: هوية ومنح يحسمها الخادم، مقيدة بالفاعل/الدور/workspace/المشروع/المورد/الفعل/بصمة المقترح/الانتهاء، ورفض المحاكاة والرموز النصية والهوية المزورة. إغلاق مسار legacy الافتراضي للكتابة وفحص المنحة عند الأثر.
5. T14: factory منفصلة للتخزين المصرح به، بلا تغيير وضع القراءة الافتراضي. 12 جدولاً وفق SQL المقفل، transaction وuser_version والتحقق من checksum/schema، وسجل audit بفاعل حقيقي؛ اختبار disk/reopen/rollback في مسار مؤقت فقط. لا CRUD أعمال أو تفعيل مخزن التطبيق أو كتابة state.json/runtime_evidence.
6. التحقق: اختبارات مركزة ثم npm test وفحص السياق، حفظ قبل/بعد وبصمات. فحوص E4 السبعة REQUIRED / NOT_RUN / NOT_WAIVED. لا مرجع جديد أو تغيير محرك/عقود أو دمج/نشر.

الأدلة المولدة من المشغل وكتابة fixtures مؤقتة معزولة مفوضة؛ التطبيق التفاعلي الحالي يظل للقراءة فقط. مراجعة ذاتية معاكسة وليست مراجعة مستقلة.
