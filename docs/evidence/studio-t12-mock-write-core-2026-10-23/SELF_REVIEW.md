# مراجعة ذاتية معاكسة — ليست مستقلة

| المحور | المراجعة والنتيجة |
| --- | --- |
| الصحة | المحاكاة تستدعي E2 ولا تصنع exit بعد التنفيذ؛ native control يبقى 3. الحقول الناقصة ما زالت INVALID/1. منح T13 تعاد مراجعتها عند الأثر. SQLite حقيقية وrollback/reopen مثبتان. |
| الوضوح | موائم المحاكاة داخل tools/t12 فقط؛ Backend لا يستورده. التهيئة والمخزن الدائم factory منفصلة؛ وضع القراءة الحالي لم يتحول إلى الكتابة. |
| المعمارية | لا تعديل محرك أو عقود أو schema. هوية/grants في الخادم، audit من actor حقيقي، 12 جدولاً طبق المصدر المثبت. ربط المسارات التفاعلية والتفعيل ما زال مفتوحاً. |
| الأمن | أغلقنا ملاحظة REQUIRED_FOR_CURRENT_ACCEPTANCE: توقيع البنود وحده لا يمنع manifest متغيراً أو بنداً زائداً؛ أضيفت مجموعة مصادر مثبتة في المضيف وفحص في Node وPython واختبارات رفض. أزيل fallback النصي، وإيصال T12 لا ينشئ كائن منحة حقيقي. |
| الموارد | مصادر T12 محددة، مدخل المضيف 128 KiB، مخرجات 16 MiB وtimeout 45s؛ هذه حدود أداة الاختبار وليست تنفيذ محول T15. لا شبكة أو كتابة من عملية Python. |

لا يثبت هذا تأهيلاً إنتاجياً أو مراجعة مستقلة. تعليق SQL الأصلي الخاص بإظهار :memory: بقي محفوظاً؛ تفويض المالك الحالي لـT14 يسمح بتجربة factory الدائمة على ملفات مؤقتة فقط مع بقاء التطبيق للقراءة. لا مسار تفعيل آلي من قبول المحاكاة.

التغيير في توقع M3 هو تطبيق رفض كتابة legacy غير المفوضة (403)، مع حفظ التصنيف والتفكيك ومعاينات adoption. بقيت اختبارات التطبيق/الاسترداد الإيجابية في M6، وأصبحت مساحتها مؤقتة ومنحها خادمية بدلاً من fallback ثابت.

فحص التسليم كشف TEST_DEFECT في حساب عضوية القفل السابق؛ عولج بفصل ملفات القفل عن اللقطات الإضافية الخمس، دون تغيير المنتج أو إعفاء اختبار. حفظت النسخة الأولية والفشل في before، والتفسير في ACCOUNTING_CORRECTION.json. نجح التحقق المصحح: 1382 ملفاً سابقاً لم تتغير، وخمسة تغييرات مأذونة داخل القفل، وخمسة ملفات إضافية لها لقطات قبلية مستقلة.
