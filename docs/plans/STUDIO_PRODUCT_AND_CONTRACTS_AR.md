# AGHR Governance Studio — إعلان المنتج ومسار تثبيت العقود

**التاريخ:** 2026-10-22. **الحالة:** وصف منتج ودليل تنفيذ تابع للمواصفات المعتمدة.  
**المصدر الحاكم:** [مرجع AGHR rc.3](../specs/aghr-rc3/AGHR_REFERENCE.md)، ثم [مواصفة Studio](../specs/aghr-rc3/STUDIO_SPECIFICATION.md). هذا المستند يستكمل الملخص السابق؛ لا يغير المرجع أو يمنح تأهيلًا أو قبول إصدار.

## 1. التغييرات الأساسية

| المجال | التغيير المستهدف |
| --- | --- |
| تنظيم بنود الحوكمة | نموذج من 13 نوعًا يفصل النوع والقوة والخطورة والسلطة والنطاق والإنفاذ. قيم `authority.level`: `enterprise` / `organization` / `project` / `component`. غياب المستوى عن `MUST` أو `MUST_NOT` خطأ يمنع قبول حفظ البند وفق العقد. متطلبات بقية القوى تتبع التدرج في rc.3 §3.3. |
| واجهة التطبيق | توسعة الأوضاع الحالية الستة إلى تغطية 16 شاشة متخصصة، مع دعم العربية والإنجليزية وحفظ لغة المصدر. لا تستخدم `scope.language` لتصفية القواعد؛ تظهر `translation_unavailable` عند غياب الترجمة. |
| إدارة المهارات | فصل التوفر والتأهيل والاستخدام؛ اختيار مناسب للمشروع والمرحلة، وتأهيل مربوط بـ`host` و`hostVersion` و`scope` و`contentHash`. تمييز `UNKNOWN_ID` و`NO_SKILL_MATCH` و`DISCOVERY_UNAVAILABLE` بأيقونة ونص ولون مميز. عدم المطابقة نتيجة صالحة؛ تعذر الاكتشاف يوقف المسار المتأثر ويعرض تحذيرًا. |
| التعلم والدروس | ربط الدرس بالمهمة والدليل والسبب المثبت أو `UNPROVEN`، وتصنيف التعليمات المقترحة ومراجعة التكرار والتعارض، ثم اقتراح اختبار أو حزمة تغيير مخولة. |
| الموافقات والتغييرات | معاينة فرق قبل كل أثر؛ موافقة مرتبطة بـ`proposal_version_hash` تُبطل عند تغيير المقترح. تصدير patch/commit لا يساوي نشرًا أو قبول إصدار. |
| النتائج والأدلة | تطبيق `task_criteria` على المخرجات الفعلية مع دليل تنفيذ؛ إظهار `NOT_RUN` و`NOT_OBSERVABLE` بصدق. لا تُستنتج `EXECUTED` أو `VERIFIED` من التحميل. |
| الصلاحيات وحالة الحوكمة | تفويض خادمي مربوط بالفاعل والمشروع والإجراء والتغيير وبصمته. في طبقة حالة الحوكمة: الوكيل/الجلسة ينتج `.aghr/runtime_evidence/{task_id}.jsonl`، وStudio يقرأه فقط، وتُرفق الأدلة بـPR قبل تقييم CI ونشره `.aghr/state.json`. |
| توليد ملفات الوكلاء | توليد بحسب المضيف والملف التعريفي والميزانية. وجود `PRIN-007` إلزامي في كل `AGENTS.md` عند L1+؛ غيابه يمنع التصدير. حالات `full/compress/compact/fail` وأدلة حفظ P0 ظاهرة، و`compact` يحتاج إقرار governance-owner واسترجاعًا مؤهلًا. |
| المراجعة والتحسين | عرض `impact.evidence` بقيم `assumed` / `benchmark` / `repo-measured`، ومواعيد المراجعة وعشرة مؤشرات. Calibration إلى `repo-measured` يحتاج حزمة تغيير مرتبطة بتشغيل eval ناجح ودلتا مقاسة وموافقة المالك؛ لا تخفيض تلقائي لأولوية P0. |
| حوكمة الحزمة نفسها | مسار موحد لتغييرات `policies/` و`schemas/` و`tools/` وتبني المهارات، مع مراجعات المالك واختبارات السلوك و`generate --check`. |
| التحقق والموارد | محرك Python AGHR المثبت المصدر الوحيد للحكم في Studio وCI؛ Node ينقل الطلبات والنتائج ولا يعيد تنفيذ قواعد التحقق. اختلاف الحكم لنفس المرشح والإصدار والإعدادات والمدخلات خطأ حرج. `eval` و`qualify` تحت حدود زمن وذاكرة مقاسة، مع `resource_limit_exceeded` وإبقاء المخرجات الجزئية. |

قيد الكتابة أعلاه يخص **الحالة الحاكمة والأدلة**؛ تعديلات شيفرة المشروع وملفات العمل تتم ضمن تفويضها المستقل. لا تمنح حقول JSON أو دور معاينة في الواجهة صلاحية فعلية.

## 2. الالتزامات الإلزامية الاثنا عشر — كيف تتحقق

كل صف أدناه التزام من Studio §3، مع آليته ومعيار اختباره. هذه معايير قبول مستقبلية؛ وجودها في الوثيقة لا يعني نجاحها في التطبيق.

| المعرّف | الالتزام والآلية المطلوبة | اختبار القبول المطلوب |
| --- | --- | --- |
| C1 | أربع طبقات مستقلة: سلطة الحوكمة، الإرشاد، ضوابط التنفيذ، الأدلة. تعلن كل شاشة طبقتها، وتفحص الأفعال عند عبور حدود السلطة. | التصفح المعتاد لا يطلب موافقة؛ أثر يغير مجالًا محميًا دون تفويض يُرفض على الخادم. |
| C2 | CI وحده ناشر `.aghr/state.json`. وصول الوكيل وStudio إلى الحالة الحاكمة للقراءة فقط. | مراقبة محاولات الكتابة خلال العمليات؛ لا مسار تعديل للحالة عبر واجهة Studio؛ مسار النشر المؤهل في CI منفصل. |
| C3 | سجل `.aghr/runtime_evidence/{task_id}.jsonl` مستقل، ومصدره الوكيل/الجلسة. يستورده Studio كعرض مشتق، ويرفقه بطلب التغيير لتقييم CI. | مقارنة بايتات الأدلة قبل/بعد العرض والإرفاق؛ غياب أي واجهة كتابة للأصل؛ عدم دمجها مباشرة في الحالة الحاكمة. |
| C4 | `scope.language` للعرض، وليس شرط انطباق أو تصفية. شارة `translation_unavailable` ظاهرة عند الحاجة. | تغيير لغة الواجهة لا يغير مجموعة القواعد المنطبقة؛ لا يقبل API مرشح لغة يخفي قواعد. |
| C5 | `authority.level` من القيم الأربع إلزامي لـ`MUST/MUST_NOT`، مع بقية حقول السلطة بحسب التدرج. المحرر يعرض الخطأ والمحرك الحاكم يرفض المدخل الناقص. | حذف المستوى أو إدخال قيمة غير معروفة يفشل؛ نتيجة Studio تطابق CLI/CI لنفس المدخل. |
| C6 | شارة `impact.evidence` لكل بند. Calibration حزمة تغيير مبنية على eval ناجح وقياس وموافقة. | رفض معايرة بلا تشغيل مرتبط أو بدليل فاشل؛ الاحتفاظ بمرجع التشغيل والدلتا والتاريخ؛ منع تغيير P0 تلقائيًا. |
| C7 | `HOST_SIGNAL` اختياري، و`NOT_OBSERVABLE` نتيجة صحيحة للملاحظة. لا تُرفع حالة التنفيذ عند غياب دليلها. | مضيف لا يقدم إشارة يعرض `NOT_OBSERVABLE`؛ تحميل المهارة وحده لا ينتج إشارة أو نجاح تنفيذ. |
| C8 | ثلاث نتائج اكتشاف منفصلة: `UNKNOWN_ID` خطأ رفض؛ `NO_SKILL_MATCH` نتيجة صالحة؛ `DISCOVERY_UNAVAILABLE` خطأ يوقف المسار المتأثر ويحذر من الثقة بالجلسة. | ثلاث حالات سلبية/إيجابية بأيقونات ونصوص وألوان مستقلة؛ لا تنفيذ بديل صامت عند تعذر الاكتشاف أو حجب الصلاحية. |
| C9 | فحص `PRIN-007` في كل `AGENTS.md` عند L1+، مع الميزانية وحفظ P0 وفحص مراحل الاختزال. | إزالة المبدأ تمنع التصدير؛ `fail` يمنع التصدير؛ `compact` بلا الإقرار والاسترجاع المؤهل مرفوض. |
| C10 | التأهيل للمفتاح الرباعي `(host, hostVersion, scope, contentHash)` مع تاريخ ودليل؛ السجل السابق يحتفظ بتاريخه. | تغير أي مفتاح يجعل التأهيل للتركيبة الجديدة `NOT_RUN` ويمنع اختيار P0 حتى التأهيل المناسب. |
| C11 | صدق الإبلاغ 100% مستقل عن تحمل السلوك الخاص بكل fixture، وهدف عام ≥95% حيث ينطبق؛ تسامح P0-Safety صفر، ومعدل النجاح الوهمي صفر. | الحالات السبع للصدق والسيناريوهات الثمانية؛ لا متوسط يخفي فشلًا حرجًا؛ غياب القياس يعرض `NOT_RUN`. |
| C12 | الافتراضي: eval ‏600 ثانية، qualify ‏3600 ثانية، وذاكرة 2 GiB لكل منهما، بضوابط فعلية للعملية وأبنائها. | تجاوز الزمن/الذاكرة يوقف الشجرة ويحفظ المخرجات ويعيد `resource_limit_exceeded`؛ يسجل الإلغاء بطلب المستخدم بسبب مستقل دون ادعاء تجاوز الموارد. Windows Job Objects أو محول المنصة يُؤهل فعلًا؛ غياب الضبط يمنع ادعاء الإنفاذ. |

تظل المطابقة الحقيقية مع CLI/CI وتأهيل المضيف والإنفاذ **NOT_RUN** إلى أن تنفذ مكوناتها واختباراتها. فحص JSON أو SQL محليًا لا يمنح هذه الحالات.

## 4. جداول SQLite الاثنا عشر

تُستخرج تعريفاتها من Studio §§5–10 دون إعادة كتابة مستقلة. فهرسة المصدر واللقطات بيانات مشتقة؛ قاعدة SQLite لا تمنح السجلات سلطة مستقلة.

| الجدول | الوظيفة |
| --- | --- |
| `workspaces` | الحزم المسجلة ونسخها وحالة التوقيع المعلنة |
| `target_projects` | المشاريع المستهدفة ومستويات الحوكمة وإعداداتها |
| `instruction_items_cache` | فهرس البنود ومصدرها وسلطتها وأثرها ومراجعتها |
| `capability_items_cache` | فهرس المهارات والأدوات والصلاحيات المعلنة |
| `skill_qualification_snapshot` | لقطة التأهيل للمضيف والإصدار والنطاق والبصمة |
| `change_packages` | المقترحات وفحوصها وفروقها وحالة سير العمل |
| `change_package_approvals` | قرارات مرتبطة ببصمة المقترح |
| `change_package_approval_history` | تاريخ القرارات الملغاة مع السبب والوقت الأصليين |
| `runtime_evidence_events` | إسقاط للقراءة من الأدلة التشغيلية |
| `verification_runs` | أوامر التحقق ونتائجها ومخرجاتها وحدود مواردها |
| `metrics_snapshots` | المقاييس الأصلية وإسقاطاتها واتجاهاتها |
| `audit_events` | سجل التدقيق مع فصل الدور الفعلي عن دور المعاينة |

## 5. ترتيب التنفيذ المصحح

| الترتيب | العمل | المخرج ومعيار الانتقال | تقدير أولي |
| --- | --- | --- | --- |
| 1 | Phase 0 — تثبيت العقود | `aghr.json` بـ`schemaVersion: 1.2`، وعقود API والبيانات والأدلة وSQLite، وحسم أسئلة G.4؛ عرض أول للقراءة فقط بلا كتابة من Studio إلى القرص | أسبوع |
| 2 | تأهيل قالب بند واحد | نموذج `SEC-001` مكتمل، ومصدره ودليله ونتائج قبول ورفض فعلية عبر `aghr validate --strict` بعد توفر محركه المثبت | 3 أيام |
| 3 | مراجعة بنود الحزمة المرجعية الحالية وترحيلها | تطبيق القالب والعقود على البنود مع حفظ هوياتها ومصادرها وقراراتها؛ عدد 47 يصف السجل الحالي في 1.2.0 وكذلك المرشح 1.3.0، ولا يحدد عدد بنود rc.3 المستقبلية | أسبوع |
| 4 | النواة التنفيذية — Phase 2 | دورة SEC-001 من التأليف إلى الفحوص والفرق والموافقة والتصدير، بعد استيفاء التصفح المتخصص في Phase 1 | أسبوعان |

هذه المدد تقديرات تخطيطية من المراجعة؛ يعاد تقديرها عند تفصيل العمل. تأهيل القالب لا يحل محل Phase 1، ولا تبدأ المراجعة الجماعية قبل وضوح العقد والقالب.

## 6. بدء المرحلة 0

مدخل المرحلة: [حزمة العقود](../contracts/aghr-rc3/README.md)، اكتمل تعريفها في `contract.1` للمراجعة والتنفيذ. فحوص البنية والتسلسل محلية؛ ربط المحرك وHTTP والعرض وCI والمضيف تبقى بوابات فعلية لم تنفذ. لا إعادة تنفيذ لمنطق AGHR في Node، ولا ترحيل جماعي أو ترقية مرجع بهذا الاستكمال.

تُبنى الإمكانات بتوسعة React/Vite/Node الحالية، مع جسر Python واحد للتحقق. المكتبات الإضافية خيارات قرار تقني؛ المصدر والنطاق ومعايير القبول تسبق الاختيار.
