## 1. Audit Taxonomy & Rating Criteria

In accordance with Directive `AFE-GOV-LEGACY-RECONCILE-002`, the coverage of every historical rule is evaluated along three independent dimensions:

1. **Textual Coverage (`TEXT`):**
   - `EXACT`: Word-for-word reproduction of the legacy rule text in the target baseline.
   - `SUBSTANTIAL`: Near-identical phrasing with minor terminology modernization.
   - `PARTIAL`: Concept is articulated using refactored or different phrasing.
   - `NONE`: Text does not appear in the target baseline.

2. **Semantic Coverage (`SEM`):**
   - `FULL`: The complete normative obligation, conditions, and intent are fully preserved without dilution.
   - `PARTIAL`: Core obligation is partially addressed, but specific constraints, scopes, or models differ.
   - `CONFLICT`: Direct normative contradiction between legacy rule and baseline invariant.

3. **Operational Enforcement (`OPER`):**
   - `AUTOMATED_TEST_EXIST`: Guarded by an executable deterministic unit/integration test in the repository.
   - `QUALITY_WORKFLOW_TESTED`: Guarded by an executable diagnostic procedure or quality workflow.
   - `PROCEDURAL_ONLY`: Prompt-level instructions without automated repository test gating.
   - `NO_OPERATIONAL_GATE`: Purely aspirational statement without verification mechanisms.

4. **Composite Re-Evaluated Status:**
   - `FULL_TEXTUAL_AND_OPERATIONAL`: Substantial/exact text + automated repository test suite.
   - `TEXTUAL_AND_SEMANTIC`: Substantial/exact text + full semantic intent (procedural).
   - `SEMANTIC_AND_OPERATIONAL`: Full semantic preservation + automated test / workflow evidence.
   - `SEMANTIC_COVERED_PROCEDURAL_ONLY`: Full semantic preservation via prompt guidance only.
   - `PARTIAL`: Confirmed gap in scope, model, or technical architecture.

## 4. In-Depth Analysis of Confirmed Partial Gaps

### 4.1 AGHR-017 (Separate Acceptance) — Gap Analysis
- **Legacy Specification:** Mandated separate developer, reviewer, and compliance auditor personas. In AGHR 1.0–1.2.0, the single AI agent was instructed to simulate multiple personas in a sequential self-dialogue.
- **Baseline v1 Resolution:** Baseline v1 explicitly rejects synthetic role-play in `GOV-022` ("Do not manufacture independence: Do not present an internal role-play, sub-invocation, paraphrase, or synthetic persona as independent human or third-party verification"). Instead, acceptance is divided between deterministic automated verification (`npm test`) and genuine sovereign owner review (`GOV-009`).
- **Audit Finding:** The *intent* (preventing unverified self-approval) is fully achieved, but the *mechanism* (simulated multi-agent staff) is formally deprecated. Classified as **`PARTIAL`** to record the departure from the legacy multi-role staff simulation.

### 4.2 AGHR-029 (Unified Change Intake) — Gap Analysis
- **Legacy Specification:** Required all change proposals, impacts, and approvals to be recorded in a centralized 12-table SQLite relational database managed by a Python `cli3.py` daemon.
- **Baseline v1 Resolution:** Replaces native SQLite runtime dependencies with lightweight, zero-dependency, human-auditable JSON schemas (`trace.schema.json`, `action.schema.json`) and Git commit ancestry (`GOV-006`, `GOV-015`).
- **Audit Finding:** The *obligation* (capturing inputs, classifying impacts, obtaining approvals) is fully covered, but the *database architecture* (SQLite daemon) is replaced by file-based Git state. Classified as **`PARTIAL`** to record the transition from relational database tracking to Git/JSON tracking.
